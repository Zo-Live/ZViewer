# ZViewer 开发计划

## 产品目标

面向现代安卓手机的离线原生漫画阅读器，界面默认使用简体中文，并支持繁體中文、English 和日本語。采用 Kotlin、Jetpack Compose、Material Design 3，最低 Android 10，目标 Android 16（API 36），提供 arm64-v8a 与 x86_64 通用 APK。

## 实施阶段

1. 建立可复现的 Gradle 工程、版本管理和发布签名。
2. 通过系统文件选择器持久授权书库；递归发现压缩包、PDF 和图片文件夹。
3. 实现 libarchive 压缩包读取、系统 PDF 渲染、APNG4Android 动画扩展及高分辨率封面缓存。
4. 完成 Material 3 书库、搜索排序、阅读进度、主题和阅读器。
5. 实现纵向连续、横向分页、缩放、可拖动浮动进度条、系统手势返回。
6. 进行格式测试、核心逻辑测试、模拟器操作验证和 release APK 验证，记录兼容性边界。

## 书库切页与设置过渡

- 书库、收藏、最近阅读支持横向跟手滑动，底部导航同步选中；点击标签平滑切换，各页分别保留网格滚动位置。
- 目录为空时三个主页均提供「选择其他目录」；无收藏或最近阅读内容时分别显示对应的引导文案，有对应内容但筛选后没有结果仍保留原有筛选提示。
- 设置页从右侧滑入，原页面左移并等比缩小到 80%，上下用主题背景色填充；返回播放反向动画，时长 360 ms。
- 设置页支持向右跟手滑动退出；拖动时设置页与书库页面同步移动，松手拖动超过 96 dp 时提交退出，否则回弹，竖向滚动和设置控件操作保持正常。
- 保留搜索、筛选、排序与当前标签，覆盖空页面、手势取消、纵向滚动、配置重建和动画中途返回；执行单元测试、模拟器功能回归及 release 端到端验收。
- 设置中的开关整行可操作，开关控件只呈现当前状态；阅读器工具栏打开的阅读设置与设置页共用同一份配置。

## 应用设置与更新

- 最后的「应用」分区使用 Info 图标，包含检查更新、默认关闭的启动检查开关、关于和 GitHub 仓库入口。
- GitHub 正式版本检查为高于已安装版本的发布提供持久缓存与 ETag 复验，并限制连接、读取、整体请求耗时和响应大小。失败或已是最新版本时可以立即重试。手动检查显示行内进度，阅读期间延后更新反馈。
- 手动检查使用 Android 系统 Toast 或新版本确认弹窗。确认后交给系统后台下载，应用回到前台且已退出阅读时打开系统安装器。
- 更新和通用诊断日志的实现细节、隐私范围及限制见架构文档；通过版本比较单元测试、模拟器交互 / 网络缓存测试及开发 Release 端到端验收。

## 封面收藏管理

- 设置 → 偏好提供「显示收藏图标」，说明为「在封面右下角显示收藏按钮」，默认开启，兼容旧配置。
- 书库、收藏、最近阅读均支持长按封面进入收藏管理；管理时强制显示收藏按钮，单击封面或按钮切换收藏。
- 文件夹按钮左侧显示同色圆形退出按钮；系统返回、设置、刷新与切换目录退出管理，搜索、筛选、排序与页面切换保留状态。
- 设备回归覆盖开关与三个页面的组合、收藏页移除最后一本、搜索空结果、返回优先级、设置持久保存及配置重建。

## 视频与阅读循环功能

- 已修复首次进入视频压缩包不自动播放、视频切换短暂黑屏：保留已完成的视图就绪状态，翻页前等待下一段首帧，并在过渡前后复用同一视频视图。新增首次打开、恢复进度与过渡逐帧回归；已连接的 API 34 模拟器上 20 项设备测试通过，release 连续切换录屏 430 帧未见整屏黑帧。开发 APK 输出到 `app/build/outputs/apk/release/`，结果详见测试记录。
- 支持视频文件夹和仅包含视频的 ZIP / CBZ、RAR / CBR、7Z；压缩包成员先解压到应用缓存，再使用 AndroidX Media3 播放。
- 图片和视频混合内容可以直接打开，按文件名自然排序后跟随垂直 / 水平翻页设置；视频页单击工具栏后显示视频进度条，图片页不显示。自动播放下一段并保存每段播放位置；与纯视频共用同一套跟手 Pager 过渡。
- 压缩包成员文件名按 UTF-8 解码（libarchive-android `Archive.setCharset` 覆盖 Android C locale 的字符集），修复中文名条目触发 `ARCHIVE_WARN` 而被误报压缩包损坏的问题；完整读取后含 PDF 的压缩包统一提示先解压。
- 纯视频与混合内容统一为同一个跟手 Pager：拖动过程中当前视频继续播放，目标页预加载并显示首帧，停靠后才移交播放；每个视频页在渲染首帧前显示 `MediaMetadataRetriever` 抽帧缓存的封面，修复了混合内容滑动时前后视频黑屏的问题；切换未完成时播完由 `onEnded` 从头重播，避免停在结尾。
- 播放器按“停靠页 + 左右相邻页”预建（最多三个）：相邻视频在离屏时就把保存位置的首帧渲染到自己的 TextureView，滑动进入时画面已经就绪；播放器只在页面离开停靠 ±1 窗口（或 Pager 组合窗口）时才释放并保存进度，拖动到一半再拉回、连续来回切换都复用同一个播放器。更远的页面（包括循环模式下的重复虚拟项）只显示封面；PlayerView 的黑色快门设为透明，首帧渲染前透出封面。修复了纯视频在循环预载时同时创建过多播放器、真机按住不动数秒后被系统关闭的问题，也避免了拖动中被回收页面的 Surface 闪断。视频播完自动前进后，再次回到该项会从头重播，用户手动暂停的视频保持暂停。
- 修复切换视频时的闪屏：视频页不再在“封面 Compose 视图 / 播放器 AndroidView”之间切换结构，而是始终使用同一个 `AndroidView`；拖动 / 切换期间目标页的播放器不再因为 target 变化被回收（此前页面仍有约 39% 可见时就会被释放，画面跳回首帧封面），相邻页提前预载并保持同一播放器实例；会话级封面缓存让重建的视图同步拿到已解码封面，进度圈只在停靠页首帧渲染前显示。另修复临近片尾切换时的解码器重置：不再根据滚动 / 切换状态切换 `repeatMode`（ExoPlayer 在距片尾约 0.6 秒时切换循环模式会重新初始化解码器输出，画面闪一下），过渡期间播完改由 `onEnded` 从头重播处理。
- 设置支持开启诊断日志、选择写入目录，以及查看、导出和清理已有日志。运行环境、授权和设置、扫描 / 阅读 / 缓存 / 更新事件与错误堆栈均写入本地，队列、文件大小和默认目录保留份数都有上限。
- 修复混合内容视频“进度前进、画面停住”：Pager 重建视频页或循环产生的重复项会让旧视图清掉新绑定的输出 Surface，而可见视图重新停靠时 `AndroidView.update` 可能被跳过。现在每个播放器只有一个 `ownerView`，交接时先解除旧视图再绑定新视图，释放临时重复视图后回退到仍停靠的活动视图；播放门槛同时要求 owner 视图的 TextureView Surface 可用，Surface 丢失时暂停、恢复后继续，播放器不再无画面空跑。
- 视频支持双指缩放和双击缩放；单击显示 / 隐藏工具栏及视频进度条，播放 / 暂停通过按钮控制，定位通过进度条完成。拖动时显示预览时间，不叠加暗色遮罩；设置可切换单段循环和仅预览。
- 设置增加循环模式和双击清除全部阅读记录，循环模式只改变到达末尾后的翻页行为，不改变在读 / 未读 / 已读判定。
- 图片循环采用 Compose 懒加载列表 / Pager 的重复页序，让首页和末页自然相邻；视频页按停靠页与相邻页预载播放器（最多三个），切换时只允许当前视频播放，其余相邻页保持暂停，更远的页面只显示封面，避免同时存在过多播放器 / 解码器。
- 视频渲染使用等比适配的 TextureView；切换内容重置缩放，横竖视频和带旋转信息的视频均交给 Media3 计算显示比例。
- 视频封面通过 Android 开源框架 MediaMetadataRetriever 抽取自然排序第一个视频的帧；视频压缩包生成封面时只提取该成员。
- 回归测试覆盖循环边界、快速切换与按钮翻页、横竖比例、播放和定位、视频封面，并维护构建与设备验证记录。

## 工程原则

- 阅读内容本地处理，仅检查和下载应用更新时联网，不申请全盘存储权限，不修改用户漫画原件。
- 使用 SAF 持久 URI 权限；重启直接展示保存的书库；授权失效时引导重新选择。
- 文件名自然排序，忽略隐藏文件与 macOS 元数据；目录直接包含图片时视为一本书。
- 文件读取、解压、PDF 渲染与图片解码在后台执行，支持取消；损坏文件显示可恢复错误。
- 解压使用应用生成的文件名，限制数量、单页及累计大小，避免路径穿越与无限展开。
- 阅读进度按书籍 URI 保存，图片与视频以媒体标识恢复位置，视频另存播放进度。设置、收藏和最近阅读持久化。缓存可在设置中双击清理，默认保留封面，开启「清理封面」后同时清理。自动清理阈值可调。
- 动图按可见性和应用生命周期播放；大图按设备尺寸限采样，支持手势与按钮缩放。
- 不支持 DRM PDF、分卷压缩包及密码保护文件；出现这些情况给出明确提示。

## 项目审查后续

1. 在大型书库测量缓存遍历、锁等待和书目刷新耗时，评估容量维护和索引刷新是否仍有进一步优化空间。
2. 对固实压缩包量化生成封面扫描与二次遍历解压的成本，再考虑复用同一次归档遍历。
3. 简化视频播放状态。`surfaceReady` 有写入而无消费者，实际播放条件使用 `surfaceAttached`，同时由布局和 200 ms 轮询更新。先补足 Surface 重建测试，再合并重复的就绪状态和暂停路径。`VideoCoverCache` 目前按写入顺序淘汰，应按实际读取刷新顺序或据此更新行为说明。
4. 新版本缺少合法 APK 时，更新弹窗应按发布状态显示。
