## 视频首次播放与切换黑屏修复

验证日期：2026-10-05。沿用工作区已有的视频过渡设计，开发阶段验证使用 `1.2.1` / `versionCode=6`，开发安装包使用 `app/build/outputs/apk/release/app-release.apk`；相关修复已纳入 `1.2.2` 正式构建。

- 定位首次播放的时序问题：媒体准备阶段会把视图已经上报的就绪状态重置为 false，而尺寸未变化时不会再次收到父容器尺寸回调。现在由实际视频表面的布局维护就绪状态，准备媒体不再覆盖它，并等待首帧后按设置播放。
- 定位切换黑屏：稳定态与过渡态使用不同的 Compose 分支，导致翻页开始和结束时重建 TextureView；同时动画原先不等待新视频首帧。现在使用固定容器及稳定 key 保留前后视图，等待新首帧和等比布局完成后再启动 240 ms 动画，过渡中均暂停。
- 修复前运行新增回归，视图连续性断言失败，确认翻页开始会丢失原视频视图。首次自动播放属于时序问题，本轮旧代码的两项自动播放用例未稳定复现，未把它们记录为修复前必现失败。
- 新增视频 ZIP 首次打开无需操作即可播放、恢复非首页的已保存播放位置、过渡前后复用视图三项设备回归；过渡测试冻结动画时钟后逐帧前进，检查两播放器暂停及 18 张截图中持续存在视频画面，结束后仅有原来的新视频视图并恢复播放。
- 非循环边界测试改为每次点击后等待过渡完成，避免等待首帧期间的第二次点击被正常的过渡保护忽略。
- 使用已连接的 API 34 模拟器 `emulator-5554`；instrumentation 临时使用 `.regression` 应用 ID 后缀，与模拟器现有应用的数据隔离。全量设备测试 **20 / 20 通过**：9 项格式与缓存测试、10 项阅读交互测试、1 项视频封面测试。过渡的 18 张截图已检查，均包含视频画面；拼图为 `test-output/video-start-transition/transition-montage.png`。

API 34 与 API 36 均完成以下流程：首次启动 → SAF 选择具体书库子目录 → 八本样书出现 → 搜索「海边」→ 收藏 / 最近阅读 → 打开 CBZ → 显示 / 收起浮动进度条 → 页码跳转 → 水平翻页 → 垂直连续 → 双指 / 双击缩放 → 放大、缩小、适合屏幕 → 深色主题 → 自定义颜色 → 系统边缘返回 → 强制停止后重新打开 → 恢复上次页码。每项通过。

`tools/ui_smoke.py` 可重复大部分流程。某些 Compose 版本的 UiAutomator 桥接不会把拖动事件稳定发送给 Slider；脚本在该桥接限制下自动使用同一面板的页码跳转作为备用验证，真实设备触摸拖动已在模拟器人工操作中确认。

## APK 低层检查

Release APK 仅包含 `arm64-v8a` 与 `x86_64`，原生库为 libarchive、libavif 和 AndroidX path rendering。`readelf -l` 显示三个库的 LOAD 段对齐为 `0x4000`，适配 Android 15 / 16 的 16 KB 页面设备；系统模拟器的 `getconf PAGE_SIZE` 返回 4096，另用 API 36 镜像完成格式测试。

内存观察：API 34 模拟器打开三页 CBZ 后应用 PSS 约 150 MiB，Native Heap 约 58 MiB；大图使用目标尺寸采样，未出现 OOM。实际手机的内存占用取决于屏幕尺寸、厂商解码器和图片编码。

## 已知边界

- 自动化 UI 对系统文件选择器与 Compose Slider 的跨进程点击 / 拖动依赖较强，遇到 StaleObject 时按 README 的手动流程复核。
- Windows WSL 的 `adb` 可连接两个模拟器；测试命令必须显式指定 `-s DEVICE`，否则可能将 APK 推送到错误设备。
- API 36 的新边到边行为和厂商定制文件选择器仍需在目标品牌手机上做一次人工验收。
