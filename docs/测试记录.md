# 测试记录

## 视频平滑切换与黑屏 / 结尾循环修复

验证日期：2026-10-06。纯视频书此前的翻页是手势结束后才开始的固定 240 ms 滑入，混合内容虽已使用 Pager 但存在两个问题：滑动时未处于播放状态的前后视频可能黑屏，切换过程中当前视频播完会停在结尾。本轮把纯视频与混合内容统一到同一套跟手 Pager 过渡，并为每个视频页补上首帧封面与过渡期循环。

- 实现：`ZoomVideoView` 不再自行识别翻页手势，未放大时把触摸交给外层 Compose Pager，由 Pager 提供跟手的拖动过渡；双指 / 双击缩放时继续请求父级不拦截手势。
- 真机崩溃修复：纯视频在循环模式下，Pager 会把同一真实页同时放进多个预载虚拟项，旧实现为每个虚拟项各建一个 ExoPlayer，真实设备上按住拖动数秒后多个解码器 / Surface 耗尽资源导致应用被系统关闭（混合内容因图片页隔开，同时存在的视频播放器少，所以不复现）。现在只给停靠页和拖动 / 切换期间将要停靠的目标页保留播放器（最多两个），其余页只显示缓存的抽帧封面；Media3 的黑色快门设为透明，播放器渲染首帧前透出封面；停靠页切换时旧播放器释放并保存进度。
- 闪屏修复：切换视频时不再在“封面 Compose 视图 / 播放器 AndroidView”两套结构之间切换，每个视频页始终是同一个 `AndroidView`，只按需挂 / 摘播放器；封面始终垫在视频下方，由不透明的视频画面自然覆盖，不再在首帧回调时切换封面可见性，消除切换瞬间的一帧空档。
- 首帧封面：`BookRepository.videoFrame` 使用 `MediaMetadataRetriever` 抽帧并缓存到封面目录的 `frames` 子目录；未停靠、暂停或准备中的视频页显示该封面，滑动时先看到下一段的封面。首次抽帧失败时稍后重试一次。
- 过渡循环：拖动或切换动画期间当前视频临时使用 `REPEAT_MODE_ONE`，并在 `onEnded` 中健壮地判断仍在滚动时重新播放，避免切换未完成时播完停在结尾。停靠后才从旧播放器切换到新播放器。
- 诊断日志：新增 `DiagnosticLog` 和设置里的“输出诊断日志”开关 /“日志目录”选择。默认写入应用专属外部目录 `logs/zviewer-日期-时间.log`；也可通过 SAF 选择 Download 等目录写入（只持有该目录持久读写授权，不需要「所有文件访问」）。除启动 / 设备信息、扫描 / 打开、视频准备 / 结束、播放错误和未捕获异常（崩溃处理器同步刷盘）外，还记录应用生命周期、播放状态（IDLE/BUFFERING/READY/ENDED）、`playWhenReady` / `isPlaying`、视频与 Surface 尺寸、首帧渲染、Surface 所有权交接、播放门槛的每个条件、播放器池大小与创建 / 释放、封面抽帧与加载耗时；真机日志据此可以逐帧对齐切换过程。目录不可写时自动回退到默认目录。
- 回归测试：`ReaderInteractionTest` 新增两项：`draggingToNextVideoKeepsCurrentPlayingAndShowsIncomingFrame`（按住拖动到一半：当前视频继续播放、目标页进入可见区域且预建但暂停的播放器、同时播放器不超过两个、目标页区域非黑；越过中线松开后完成切换并播放）和 `currentVideoLoopsWhenEndedDuringTransition`（过渡中把当前视频定位到结尾，确认它循环回开头继续播放）；`DiagnosticLogTest` 验证日志文件写入与内容；原有过渡用例改写为新的 Pager 形态。

## 混合内容视频假播放（进度前进、画面停住）修复

验证日期：2026-10-06。混合图片 / 视频内容在图片与视频、视频与视频之间来回切换（尤其是向前切换、拖到一半再拉回撤销）后，视频偶发出现进度条继续前进但画面停在最后一帧的情况；纯视频不受影响。

- 定位过程：在模拟器上以 release 构建复现并加入临时日志，发现 Pager 会在滑动与循环模式下反复销毁 / 重建视频页的 `AndroidView`。开启循环时，同一真实页面对应两个虚拟 Pager 项，会同时为同一个 `VideoPlaybackState` 创建两个视图：新视图先绑定播放器，旧视图的 `onRelease` 随后执行并清空播放器输出 Surface；而 Compose 在页面重新停靠时可能跳过 `AndroidView.update`，可见视图不会重新绑定，播放器于是继续走时钟但不再渲染。播放门槛此前只检查 `ready`，不检查 Surface，因而表现为“进度走动、画面不动”。
- 修复方式：`VideoPlaybackState` 记录唯一持有 surface 的 `ownerView`；`bindOwner` 在交接时先解除旧视图、再绑定新视图，`releaseOwner` 只允许当前 owner 清理，并在释放的是临时重复视图时回退绑定仍然停靠的活动视图。`VideoPage` 在激活状态变化时重新确认所有权，`ZoomVideoView` 在 detach 时上报 surface 不可用。播放门槛新增 `surfaceAttached` 条件，owner 视图没有可用 TextureView Surface 时保持暂停，surface 恢复后才继续播放，从机制上杜绝“无画面空跑”。
- 回归测试：新增 `ReaderInteractionTest` 三项用例：显式 owner 交接（含临时重复视图释放后回退到停靠视图）、视频页视图被销毁重建后画面仍在变化、拖过中线再拉回的视频仍在变化；新增 `moving.mp4` 动态测试样本（独立目录，避免影响封面自然排序用例）。`FixtureDocumentsProvider` 现在复制 assets 前清空目录，避免历史测试文件残留导致封面用例误判。
- `./gradlew :app:testReleaseUnitTest :app:lintRelease :app:assembleRelease` 通过；10 / 10 项单元测试通过，Lint 为 0 错误、23 条非阻断提示。

## 混合图片视频与视频切换优化

验证日期：2026-10-05。混合图片和视频的文件夹 / 压缩包现在直接打开并锁定水平翻页；图片页不显示视频进度条。纯视频切换时，当前播放器在等待下一视频首帧和 240 ms 过渡期间继续播放，下一播放器保持暂停，过渡结束后只保留一个播放中的视频。混合内容从图片切入视频时，预加载播放器保持暂停，页面停靠且媒体准备完成后解除播放门控，避免因等待离屏首帧而卡住；切换到下一个视频时仍只允许当前页播放。

- 压缩包解压清单按成员类型保存图片 / 视频；完整读取且含 PDF 的压缩包统一提示先解压，即使同时包含图片或视频，读取失败的压缩包仍走损坏 / 权限错误提示。混合文件夹封面按自然排序的首个媒体生成。
- 新增 `ReaderInteractionTest` 图片→视频→视频回归，检查从图片进入视频后位置持续推进、切换后的目标视频可播放，以及相邻播放器同时只有一个处于播放状态。
- 按开发构建的反馈修正两个问题。其一，中文名条目此前被误报为压缩包损坏：libarchive 在 Android C locale 下读取带 UTF-8 标志的条目会抛出 `ARCHIVE_WARN`（`Pathname cannot be converted from UTF-8 to current locale.`），含中文名的混合压缩包在识别到 PDF 之前就中断。现在打开归档前调用 `Archive.setCharset(archive, "UTF-8")` 覆盖当前 locale 字符集，中文名的图片、视频和含 PDF 混合归档都能正常读取；完整读取后若发现 PDF 再统一提示先解压。
- 其二，混合内容中视频播完自动前进后，播放器停在结尾帧且 `playRequested` 被置为 false，返回该视频时画面卡住。现在重新激活已播完（`STATE_ENDED`）的播放器时回到开头并按预览设置恢复播放，用户手动暂停（非 ENDED）的选择不受影响；同时确认离开视频页后离屏播放器保持暂停、位置不再前进。
- 新增 `FormatIntegrationTest` 含 PDF 混合归档提示（UTF-8 中文名 / ASCII 名）与 UTF-8 中文名条目解压顺序回归；新增 `ReaderInteractionTest` 混合内容离屏暂停、返回已播完视频重播回归，并把播放状态断言限定到当前页对应的播放器。
- `./gradlew :app:testDebugUnitTest :app:lintDebug` 与 `./gradlew :app:connectedDebugAndroidTest` 在 API 34 模拟器 `emulator-5554` 上 **26 / 26 通过**，覆盖混合内容水平锁定、图片 / 视频页工具栏差异、视频切换播放状态、离屏暂停、结束重播、自动续播、定位、循环和格式缓存。
- release APK 在模拟器上验证：混合文件夹图片切视频后位置持续推进（00:01→00:03），播完自动前进，返回后从头重播；中文名混合 ZIP 打开且视频可播放；含 PDF 的混合 ZIP 显示先解压提示且不再出现损坏提示。验收脚本与截图保存在 `test-output/mixed-charset-video-replay/`。

- 自动化 UI 对系统文件选择器与 Compose Slider 的跨进程点击 / 拖动依赖较强，遇到 StaleObject 时按 README 的手动流程复核。
- Windows WSL 的 `adb` 可连接两个模拟器；测试命令必须显式指定 `-s DEVICE`，否则可能将 APK 推送到错误设备。
- API 36 的新边到边行为和厂商定制文件选择器仍需在目标品牌手机上做一次人工验收。
