## 长篇页码拖动调度（开发验证）

- 在 Android Emulator API 34（`emulator-5554`）上，用 360 页 JPEG、动态 WebP 和扫描图 PDF 比较 250 ms 基线与新开发包。设备端每 17 ms 更新滑块，从第 21 页起向前扫约 310 页，再反向扫约 230 页。分别按住 700 ms 和立即松手，核对目标页及画质恢复。实际落点为第 100 或 102 页，三个格式均就绪。
- 按住组逐帧识别到的不同中间预览页数，JPEG 从 13 到 12，动态 WebP 从 12 到 10，PDF 从 0 到 8。立即松手组依次为 8 到 4、10 到 12、0 到 8。录屏只计入实际采到的画面，测试页数和触控频率不能用来推算每秒解码吞吐量。
- 用设备时钟对齐最后一次移动、松手和最终画质首帧。按住组从最后一次移动到最终画质依次为 1.00 → 1.27 秒、1.21 → 1.21 秒、1.22 → 1.04 秒。立即松手组从松手到最终画质依次为 0.96 → 1.80 秒、0.87 → 0.94 秒、0.96 → 0.69 秒。JPEG 立即松手复测为 0.66 → 1.06 秒，中间页计数为 9 → 13。录屏相关帧的采样间隔最大 150–429 ms，JPEG 松手时延在两轮都变长。桌面模拟器的录屏结果不足以给出实体手机的时延或稳定帧率。
- 31 项 Release 单元测试通过，Lint 为 0 错误、42 条警告，开发 APK 通过 v2 签名及 16 KiB ZIP 对齐检查。读图、视频和格式的 38 项设备回归在调整快慢拖停留阈值前通过，最终版本通过 4 项阅读进度条专项测试，覆盖水平翻页、垂直连续、跨视频定位和片内拖动。录像、触控时间戳、逐帧统计和构建日志位于 `test-output/scrub-scheduling/`。

## 视频切换闪屏修复（拖动 / 切换期间不再回收播放器）

验证日期：2026-10-06。真机 `test.zip`（1 图 2 视频，循环模式）在滑动切换视频时闪屏；该问题由上一条「优化视频切换动画」引入，包含两个原因：目标页的播放器在仍可见时被释放，以及临近片尾时切换 `repeatMode` 导致解码器输出被重置。

- 原因一：真机日志显示“拖到一半再拉回”/ 连续来回切换时，目标页的播放器在页面仍有约 39% 可见时被释放（`Surface 尺寸 0x0` → `释放播放器`），下一次拖动再重新创建播放器并从首帧重新渲染；一次手势内 target 反复切换会反复创建 / 销毁播放器，画面在实时帧与首帧封面之间跳动。模拟器上用同一份 `test.zip` 复现了相同日志序列（目标页 `hasPlayer` 在滚动中变 false、播放器被释放）。
- 原因二：上一条 commit 为了“过渡期间当前视频播完不停在结尾”，在拖动 / 切换动画期间把 `repeatMode` 临时设为 `REPEAT_MODE_ONE`、停靠后再改回。真机与模拟器日志在临近片尾的切换中都出现 `视频尺寸 0x0` → `BUFFERING` → 重新渲染首帧；探针测试确认在距片尾约 0.6 秒时切换 `repeatMode` 会触发 4 次 `onVideoSizeChanged(0x0)`（远离片尾切换则不会），这是解码器输出被重新初始化，画面会闪一下。

## 混合内容视频假播放（进度前进、画面停住）修复

验证日期：2026-10-06。混合图片 / 视频内容在图片与视频、视频与视频之间来回切换（尤其是向前切换、拖到一半再拉回撤销）后，视频偶发出现进度条继续前进但画面停在最后一帧的情况；纯视频不受影响。

- 定位过程：在模拟器上以 release 构建复现并加入临时日志，发现 Pager 会在滑动与循环模式下反复销毁 / 重建视频页的 `AndroidView`。开启循环时，同一真实页面对应两个虚拟 Pager 项，会同时为同一个 `VideoPlaybackState` 创建两个视图：新视图先绑定播放器，旧视图的 `onRelease` 随后执行并清空播放器输出 Surface；而 Compose 在页面重新停靠时可能跳过 `AndroidView.update`，可见视图不会重新绑定，播放器于是继续走时钟但不再渲染。播放门槛此前只检查 `ready`，不检查 Surface，因而表现为“进度走动、画面不动”。
- 修复方式：`VideoPlaybackState` 记录唯一持有 surface 的 `ownerView`；`bindOwner` 在交接时先解除旧视图、再绑定新视图，`releaseOwner` 只允许当前 owner 清理，并在释放的是临时重复视图时回退绑定仍然停靠的活动视图。`VideoPage` 在激活状态变化时重新确认所有权，`ZoomVideoView` 在 detach 时上报 surface 不可用。播放门槛新增 `surfaceAttached` 条件，owner 视图没有可用 TextureView Surface 时保持暂停，surface 恢复后才继续播放，从机制上杜绝“无画面空跑”。
- 回归测试：新增 `ReaderInteractionTest` 三项用例：显式 owner 交接（含临时重复视图释放后回退到停靠视图）、视频页视图被销毁重建后画面仍在变化、拖过中线再拉回的视频仍在变化；新增 `moving.mp4` 动态测试样本（独立目录，避免影响封面自然排序用例）。`FixtureDocumentsProvider` 现在复制 assets 前清空目录，避免历史测试文件残留导致封面用例误判。

## 设备手动验收

API 34 与 API 36 均完成以下流程：首次启动 → SAF 选择具体书库子目录 → 八本样书出现 → 搜索「海边」→ 收藏 / 最近阅读 → 打开 CBZ → 显示 / 收起浮动进度条 → 页码跳转 → 水平翻页 → 垂直连续 → 双指 / 双击缩放 → 放大、缩小、适合屏幕 → 深色主题 → 自定义颜色 → 系统边缘返回 → 强制停止后重新打开 → 恢复上次页码。每项通过。

`tools/ui_smoke.py` 可重复大部分流程。某些 Compose 版本的 UiAutomator 桥接不会把拖动事件稳定发送给 Slider；脚本在该桥接限制下自动使用同一面板的页码跳转作为备用验证，真实设备触摸拖动已在模拟器人工操作中确认。

## APK 低层检查

Release APK 仅包含 `arm64-v8a` 与 `x86_64`，原生库为 libarchive、libavif 和 AndroidX path rendering。`readelf -l` 显示三个库的 LOAD 段对齐为 `0x4000`，适配 Android 15 / 16 的 16 KB 页面设备；系统模拟器的 `getconf PAGE_SIZE` 返回 4096，另用 API 36 镜像完成格式测试。

内存观察：API 34 模拟器打开三页 CBZ 后应用 PSS 约 150 MiB，Native Heap 约 58 MiB；大图使用目标尺寸采样，未出现 OOM。实际手机的内存占用取决于屏幕尺寸、厂商解码器和图片编码。

## 已知边界

- 自动化 UI 对系统文件选择器与 Compose Slider 的跨进程点击 / 拖动依赖较强，遇到 StaleObject 时按 README 的手动流程复核。
- Windows WSL 的 `adb` 可连接两个模拟器；测试命令必须显式指定 `-s DEVICE`，否则可能将 APK 推送到错误设备。
- API 36 的新边到边行为和厂商定制文件选择器仍需在目标品牌手机上做一次人工验收。
