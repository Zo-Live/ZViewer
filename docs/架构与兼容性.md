# 架构与兼容性

## 分层

- `MainActivity`：单 Activity、Compose、边到边显示。
- `LibraryViewModel`：应用状态、目录授权、扫描 / 打开任务、错误映射、设置与阅读记录。
- `PreferenceStore`：SharedPreferences 保存 URI、书目 JSON、页码、收藏、设置和日志选项。书目数据是可通过重新扫描恢复的索引。
- `DiagnosticLog`：按需开启的本地诊断日志，包含应用版本 / 构建类型、Android / 设备 / ABI、显示与字体配置、内存与可用存储、目录授权概况、设置快照、生命周期、扫描 / 打开耗时与格式统计、阅读页码、缓存清理、图片 / PDF / 视频错误、更新请求和崩溃堆栈。每条记录包含时间与时区、级别、分类、进程、线程和运行时长；移除 Surface 所有权、播放门槛、播放器池和虚拟页滚动等专项跟踪。512 条有界队列在 IO 协程中串行写入，单条最多 16 KiB、单文件约 2 MiB，达到上限停止常规记录但保留崩溃写入。默认目录最多保留 5 份日志；用户选择的 SAF 目录不自动删除旧文件。目录不可写时回退默认目录，关闭后停止采集。常规事件使用书目标识摘要，URI 脱敏，不记录书名或文件内容；异常堆栈仍可能包含文件路径，分享前可自行查看。
- `BookRepository`：DocumentsContract 批量查询、后台解压、PDF 渲染、视频文件缓存、封面与页面缓存。
- `PdfDocument` / `PdfReaderPages` 管理 PDF 会话、可见页优先级与相邻页预渲染。
- `ReadingCache`：统一统计与回收阅读文件、封面及视频首帧；按最近使用时间淘汰，通过引用计数保护会话与进行中的 I/O。
- `ImageLoader`：根据 PNG 数据块识别 APNG；AVIF 由 APNG4Android + libavif 解码；其余格式交给系统 ImageDecoder。
- `ZoomImageView`：通过 AndroidView 接入原生图片矩阵、双指缩放、双击及平移；未缩放时交由 Compose 列表 / Pager 处理翻页。
- `ReaderPaging`：将 Compose 列表 / Pager 的虚拟位置映射到真实页码，循环模式从重复页序的中部开始；首尾本身就是相邻项目，无边缘甩动后的突然跳页。重复页只按需创建，可见动画仍按虚拟位置管理。
- `VideoReader`：纯视频与混合内容统一使用 Pager 切换。播放器按“停靠页 + 左右相邻页”预建（最多三个），相邻视频在离屏时就把保存位置的首帧渲染到自己的 TextureView，滑动进入时画面已经就绪；播放器在页面仍处于 Pager 组合窗口期间不会被回收，因此“拖到一半再拉回”、连续来回切换时不会反复销毁 / 重建 Surface 而闪屏，也避免了循环模式下的重复虚拟项各自创建播放器。非相邻页只显示 `MediaMetadataRetriever` 抽帧并缓存的封面；会话级封面缓存只保留最近几页，避免长视频书占用过多内存。所有视频页共享同一个 `AndroidView` 结构：没有播放器时只显示封面，有播放器时挂到同一个视图上，不在“封面页 / 播放器页”之间切换视图结构。滑动是跟手的，拖动期间当前视频继续播放，停靠后才把播放移交给新视频；不再需要播放器的播放器释放并保存进度。每个播放器只允许一个 `ownerView` 持有输出 Surface，交接时先解除旧视图再绑定新视图，旧视图或临时重复视图释放时不会清掉当前 Surface，并会回退到仍停靠的活动视图；页面激活状态变化时重新确认所有权。播放门槛同时要求 owner 视图的 TextureView Surface 可用，Surface 丢失时暂停、恢复后继续。Media3 PlayerView 的黑色快门被设为透明，播放器尚未渲染首帧时会透出下方缓存的封面；封面永远垫在视频下方，由不透明的视频画面自然覆盖，不在首帧回调时切换可见性；进度圈只在停靠页且首帧尚未渲染时显示，避免预载 / 拖动页面闪现。封面首次抽帧失败时会在稍后重试一次。`repeatMode` 只由“单个视频循环 / 循环模式”设置决定，不随滚动 / 切换变化：ExoPlayer 在临近片尾时切换循环模式会重新初始化解码器输出（视频尺寸归零、画面重新渲染首帧）而闪屏；过渡期间播完的情况由 `onEnded` 回调从头重播处理。视频播完自动前进后再次返回该视频会从头重播，用户手动暂停的选择不受影响。切换及退出保存毫秒级进度，退到后台暂停，返回前台保留用户的暂停选择。
- `ZoomVideoView`：Android 开源框架 GestureDetector / ScaleGestureDetector 识别单击、双击、缩放和平移；未放大时把手势交给外层 Pager，由 Pager 提供跟手的翻页过渡（AndroidView 与 Compose 手势共存），放大或双指操作时请求父级不拦截手势以平移画面。Media3 PlayerView 使用 TextureView 和 FIT 等比布局，播放器视图下方叠加首帧封面 ImageView，切换时重置缩放。
- `ui/`：Material 3 Scaffold、NavigationBar、Card、FilterChip、DropdownMenu、ModalBottomSheet、Slider 与 Dialog。
- `LibraryScreen`：书库、收藏、最近阅读共用封面与收藏管理状态。`show_favorite_icon` 默认开启并由 SharedPreferences 保存；管理状态通过 `rememberSaveable` 保存，跨标签和配置重建保留。封面长按进入管理，显示收藏按钮的条件为「设置开启或正在管理」，管理时封面单击复用 `toggleFavorite`。管理状态的返回处理优先于收起搜索；退出按钮、设置与刷新清除管理状态，搜索、筛选、排序不清除。

## 页面导航

书库导航由 `HorizontalPager` 承载书库、收藏和最近阅读三个页面，底部导航与 `currentPage` 同步，点击标签使用 `animateScrollToPage`，横向手势由 Pager 与纵向封面网格协调；空结果与未授权目录时同样可以切页。各页独立保存网格位置，搜索、筛选、排序及收藏管理状态由外层共用。当前网格离开顶部后，回顶按钮从右下方浮出，点击后平滑滚回顶部。回顶和退出收藏管理按钮均为圆形。收藏管理的退出按钮在顶部占据右下角，回顶按钮出现时向左移。点击回顶后，两枚按钮随最后一段滚动同步移动，列表到顶时回顶按钮已消失，退出按钮已移回右下角。已授权书库的目录入口位于「设置 → 书库与存储」。

共用搜索栏使用 `AnimatedVisibility` 从顶部展开，280 ms 内轻微下滑并淡入，标题、筛选与封面区域随占用高度平滑下移；关闭时以 220 ms 向上收起并淡出，内容同步回到原位。高度与位移动画采用 `FastOutSlowInEasing`，支持动画中途反向切换，系统关闭动画时直接完成状态切换。关闭搜索仍清空关键词，切页、阅读与设置返回保留原有搜索状态及网格位置。

阅读状态筛选在独立的一行内横向滚动，两侧留白与页头的 24 dp 内容边距对齐。某侧还有内容时，筛选标签在到达对应的留白前逐渐变透明。筛选行先按页边距裁剪并绘制淡出，再对绘制结果施加横向拉伸。所有筛选项可见时也会响应边界拖动，拉伸幅度随拖动距离逐渐减缓，并限制在留白内以保留标签轮廓。松手后通过弹簧动画恢复原位。分页手势从行外触发。空状态书本图标以三个标签共用的分页视口中点定位，标题和说明按应用语言分行。窗口高度有限时，空状态从筛选区下方开始，说明区域可滚动。

设置导航使用共享进度驱动的横向过渡：点击设置或返回时以 360 ms 的 `FastOutSlowInEasing` 动画推进，设置页从右侧进入，书库页面同步左移并从中心等比缩小到 80%；设置页右滑时直接跟随手指移动，两层内容按同一进度变换，松手后拖动距离达到 96 dp 就继续退出，否则回弹。背景使用当前主题背景色填充，竖向滚动和控件点击保持原行为。`rememberSaveableStateHolder` 保留离场页面的标签、搜索、筛选、排序与网格状态，支持配置重建及阅读后返回。过渡期间拦截触摸，离场内容移出无障碍操作树，设置的返回处理优先于书库的搜索 / 收藏管理返回处理，系统返回可中断进入动画。

## 数据流程

「设置 → 偏好」的第一项为语言。应用独立保存语言代码，默认简体中文。切换语言时重建 Activity 以加载对应的 Android 字符串资源，并恢复设置页及书库导航状态。应用主题、语言、每行封面数和阅读模式共用菜单控件，整行可点击，无障碍树提供菜单按钮的名称、当前值和展开状态，以及各选项的选中状态。阅读器快捷设置和书库排序也使用相同的菜单定位。菜单与触发控件的末端对齐，以完整控件的上下边界作为锚点，由 Material 3 `DropdownMenu` 决定弹出方向和窗口边距。

设置菜单行右侧按当前值和图标的实际宽度排版，剩余宽度分给标题。「开源许可」的导语随应用语言切换，`open_source_notices.txt` 由 `tools/collect_licenses.py` 收集许可原文。

用户选择目录 → SAF 持久读取授权 → 后台递归扫描 → 书目索引 → 按需生成封面 → 打开书籍 → 准备页面 → 解码当前 / 邻近可见页面或创建当前视频播放器 → 保存页码和视频位置。

书库名称、文件夹媒体、压缩包成员与封面选取共用 `NaturalOrder`。数字、拉丁字母、中文依次排列，数字按数值比较，中文使用词组字典确定多音字读音。含假名的文件名用日语校对规则处理相邻假名和汉字，纯汉字使用拼音规则。压缩包缓存清单保留原始文件名，每次打开按当前规则排列。升级后首次打开未变更的书籍时，将旧阅读页码和视频进度映射到同一文件。

ZIP、RAR、7Z 使用 libarchive JNI，同一入口读取多种容器。Android 的 C locale 无法把带 UTF-8 标志的条目文件名转换为当前 locale，libarchive 会抛出 `ARCHIVE_WARN` 并中断读取，中文名压缩包因此被误判为损坏；打开归档前通过 libarchive-android 的 `Archive.setCharset` 把当前字符集覆盖为 UTF-8，使中文名条目可以正常读取。压缩包首次打开将支持的图片和视频流式写入私有缓存，成功后才写入完整清单；完整读取后只要发现 PDF，就提示先解压，无论是否同时存在图片或视频；取消或失败会清理未完成目录。对于固实压缩包，这比每翻一页重新解压前面的数据更可预测，但首次打开大书需要等待。

视频文件夹使用 `video-folder` 书籍类型，视频压缩包首次打开时也会把视频成员顺序解压到私有临时目录，再交给 Media3 播放。图片和视频在同一个文件夹或压缩包内时作为混合内容打开，按自然排序并跟随阅读方向设置（垂直翻页或水平翻页），按当前页类型显示图片或视频控制。支持的扩展名包括 MP4、M4V、MKV、WebM、AVI、MOV、3GP、3G2、MPG、MPEG、TS、MTS、M2TS、FLV、WMV、OGV、VOB、RM 与 RMVB，实际编码能力由设备 Media3/系统解码器决定。

封面独立生成：先读取目录找到自然排序第一个媒体，图片解码首图，视频使用 Android 开源框架的 MediaMetadataRetriever 抽取首个视频的帧，按比例缩小到 1000 × 1000 范围并缓存 JPEG。视频文件夹直接读取 SAF URI；视频压缩包只提取首个视频成员到临时文件，生成封面后删除，保留单视频 4 GiB 上限。生成失败时书库保留占位图；不为了封面而完整展开整本压缩包。PDF 封面优先使用已有阅读副本或原始 SAF 可寻址描述符；遇到管道等不可寻址来源才临时复制，生成封面后立即删除。

打开 PDF 时优先使用已有副本或可寻址的 SAF 描述符。不可寻址的来源会流式复制到缓存。每次阅读复用一个系统 `PdfRenderer`，退出时释放。垂直连续与水平翻页模式均优先渲染当前可见页，并预渲染视口前后各一页。翻页和跳页会更新渲染优先级，离开预载范围的位图交回系统回收。位图直接显示，渲染宽度限制为 480–2560 像素，并按应用内存额度限制单页像素数。

## 生命周期与性能

- I/O、解压、PDF 渲染和图片解码运行在 `Dispatchers.IO`；流式操作检查协程取消。
- 封面生成并行数为 2，同一本书的准备和封面生成分别通过 Mutex 串行；同一页面的文件缓存也串行写入，避免循环中多个可见副本争用临时文件。
- 图片阅读器采用 LazyColumn 或 HorizontalPager；循环只增加虚拟项目数，不复制媒体文件，记录的页码始终为真实页码。水平翻页预备前后各一页以便自然滑入；仅当前页的动画播放，垂直模式则播放可见动画；离屏、退到后台或退出时停止。
- 纯图片阅读器打开时先加载当前页，当前页加载完成或报错后才启动相邻页加载。图片解码在后台最多同时执行两项。静态图片将视口宽度的两倍用作解码目标，GIF、动态 WebP 和 APNG 以视口宽度为目标并限制解码像素数。APNG 在动画库分配帧缓冲前确定采样倍数，避免视图设置边界后重复解析。动画随页面可见性和视图附着状态启停，有限次数动画自然播放完后保持末帧。
- 压缩包与 PDF 缓存以 URI 摘要、修改时间和文件大小为键；图片 / 视频文件夹额外保存按 URI 排序的成员签名，覆盖每个媒体的 URI、名称、修改时间与大小，避免改名或非最新成员变化被最大时间 / 总大小掩盖。签名随书目索引持久化。每次完整扫描成功后，比较上次索引，删除变化或移除书目的旧缓存。开启「仅保留当前书库缓存」后会扫描当前书库，并在每次扫描成功后清理未纳入当前书库的临时文件、完整封面和视频首帧。扫描失败或取消时保留缓存，仍被阅读或生成任务引用的旧缓存延迟到最后一个引用释放后删除。
- 完整书库封面与视频首帧保存在 `files/covers/`（首帧位于 `frames/`），不因未使用时长、重新启动、Android 回收缓存目录或应用容量自动清理而删除。旧版 `cache/covers/` 中已完成的 JPEG 在 IO 线程迁移并复用；临时源文件留在 `cache/covers/`。首次为旧文件夹索引补充成员签名时，原有大小、修改时间和类型一致即沿用旧封面，建立签名基线。
- `cache/books/`、`cache/covers/` 与 `files/covers/`（含首帧和写入中的临时文件）全部计入设置页缓存大小。合计达到用户设置的清理阈值时，只按最近使用时间回收闲置阅读文件和未完成的临时文件，尽量降至阈值的三分之二；完整封面和首帧始终保留。删除失败时按实际剩余大小核算，不虚报释放空间。
- 「书库与存储」中的「仅保留当前书库缓存」和「自动补全封面」均默认关闭。开启「自动补全封面」后，书库页在前台且扫描完成时由后台协程逐本生成缺失的封面，覆盖离屏及被筛选隐藏的书目；进入设置、开始阅读或离开前台时暂停，回到书库时继续检查缺失封面。单本生成失败不影响其余书目。
- 「清理封面」默认关闭，双击清理时保留完整封面和视频首帧；开启后同时清理，缓存项说明才追加「和封面」。自动补全在清理完成并返回书库后生成书目封面，阅读页的视频首帧仍按需生成。`cache_limit_mib` 默认 1536 MiB，范围 256–8192 MiB、步长 256 MiB；拖动时显示当前容量，松手保存并立即检查回收，更新设置页缓存统计。每次自动回收从持久设置读取上限，重启后继续生效；按容量自动回收始终保留完整封面。
- 阈值滑条后是「移除后台时清理阅读缓存」，「清除阅读记录」后是「移除后台时清除阅读记录」。两个开关默认关闭。Android 最近任务移除事件触发已开启的清理，缓存清理沿用「清理封面」设置。在 Android 11 及以上，系统提前结束进程时，在同次开机的下次启动核对旧任务卡片并补做清理。
- 启动、退出阅读立即检查；打开完成、封面 / 页面 / 首帧处理完成、每个解压成员完成及单文件写入每跨过 16 MiB 均请求后台检查，通过合并通道与 500 ms 间隔合并连续请求。遍历和删除只在 IO 线程执行。
- `open()` 从准备开始保留书籍引用，成功后交给 `BookSession`；退出时由 `close(session)` 释放，失败与取消也会释放。封面解码、页面写入及视频抽帧使用短期引用；同一把锁协调引用获取与淘汰，避免回收正在使用或尚未写完的文件。仓库随 ViewModel 清理时停止后台任务。
- 自动回收阈值不是硬磁盘配额；完整封面或受保护的一本书已超过阈值时，先清理其他闲置临时内容，允许总量高于目标；当前书保留至退出后再回收，封面仍保留。整本解压、原图质量、相邻页预载和播放器池保持不变；不以反复解压或有损重编码换取空间。设置中可双击「清理阅读缓存」手动删除闲置临时文件，是否同时删除完整封面由「清理封面」开关决定。
- 视频按选定的垂直或水平方向平滑切换，混合内容同样跟随该设置；Pager 原生拖动提供跟手过渡，拖动与切换动画期间当前视频继续播放，停靠后才把播放移交给新视频。停靠页与左右相邻页各持有一个预载播放器（最多三个），相邻视频在离屏时已渲染好保存位置的首帧，拖动进入不需要临时创建 / 销毁 Surface，因此不会闪屏；更远的页面（包括循环模式下的重复虚拟项）只显示缓存的抽帧封面，避免多个解码器 / Surface 同时存在。播放器页的黑色快门设为透明，首帧渲染前透出封面；进度圈只在停靠页且首帧尚未渲染时显示。`repeatMode` 不随滚动 / 切换切换（临近片尾改循环模式会重置解码器输出而闪屏），过渡期间播完由 `onEnded` 从头重播。视频文件夹直接交给 Media3 读取 SAF URI，压缩包使用已解压的文件。播放结束自动进入下一段，设置可改为单段循环或仅预览。每段视频单独保存播放位置，完成播放后归零；书籍页码只由翻页更新，保存上一个视频的位置不会回写当前页码。
- 视频的双击只负责缩放；单击同步显示 / 隐藏底部工具栏和播放进度条。进度条左侧是播放 / 暂停按钮，上方显示当前时间与全长；拖动显示目标时间，松手提交定位，不添加暗色覆盖层。后台暂停不重新读取旧播放位置，退出释放播放器。

## 文件与隐私

正式 Manifest 为 GitHub 更新申请 INTERNET 和 REQUEST_INSTALL_PACKAGES 权限。安装来源授权与安装确认均由 Android 处理。应用不申请外部存储读写或 MANAGE_EXTERNAL_STORAGE 权限，只读取用户授权的目录，不删除、移动或改写漫画原件。禁用备份与设备迁移，避免无效 URI 授权随应用数据迁移。

压缩包成员永远写入应用生成的序号文件名，不将成员路径直接拼接到输出目录。只接收常规图片和视频文件，忽略隐藏文件、macOS 元数据和非媒体条目，不提取符号链接。存在页数、递归深度、单页及总解压大小限制。

阅读进度按书籍 URI 保存；视频另按书籍和视频序号保存播放位置；设置、收藏、最近阅读持久化；缓存可清理且不影响原文件。设置中的“清除阅读记录”和“清理阅读缓存”均为双击执行；“清除阅读记录”移除所有页码和视频位置，“清理阅读缓存”删除临时解压文件，仅在开启“清理封面”后同时删除完整封面和视频首帧。

测试使用的文件提供器只存在于单独的 `androidTest` APK；不会出现在正式应用中。测试样本为工具生成的原创占位图，无用户漫画内容。

## 系统支持

最低 API 29，编译 / 目标 API 36。现代 ARM64 手机为主要目标；x86_64 用于模拟器。启用预测返回回调并显示跟手过渡；低版本系统使用相同返回逻辑。Android 16 强制边到边布局所需的状态栏、导航栏和手势区域均由 Compose Insets 处理。

正式包的 `libarchive-jni.so`、`libavif_android.so`、`libandroidx.graphics.path.so` 的 ARM64 与 x86_64 ELF LOAD 段需具有至少 16 KB 对齐，APK 也需通过 `zipalign -P 16` 检查。构建和验证命令见测试记录。

## 应用更新

- 设置末尾的「应用」分区使用 Info 图标，依次提供「检查更新」（显示当前版本）、「启动时检查更新」（默认关闭）与「关于 ZViewer」。开关整行可操作，保留统一的对齐、主题色和无障碍语义。
- `UpdateChecker` 在 IO 线程请求 `https://api.github.com/repos/Zo-Live/ZViewer/releases/latest`，仅接受正式版本，按主 / 次 / 修订号进行数值比较。只选择 `ZViewer-x.x.x-release.apk` 通用包，并校验 HTTPS、官方仓库路径与资源大小；草稿、预发布、非法 JSON 或标签不会被当成最新版本。
- 高于当前安装版本的正式发布才写入持久缓存。手动检查 60 秒内复用，启动检查 6 小时内复用，过期后通过 ETag / 304 重新验证。网络错误、HTTP 异常和无更新结果可立即再次请求。连接超时 5 秒、读取超时 8 秒、总请求截止 15 秒，响应最多 512 KiB。
- 启动只在 ViewModel 初始化时按设置检查，配置重建不重复检查；自动检查在发现新版本时提示，最新或失败时保持安静。手动检查使用行内进度指示，不弹进度对话框。
- 新版本使用确认弹窗。底部圆角短提示沿用阅读页码的深浅背景色与 72% 不透明度，并带淡入淡出与滑动过渡。主页面和设置页共用同一底部位置，短提示位于主页面悬浮按钮上方。约 3.5 秒后消失，显示时长遵循系统无障碍设置，点击页面任意位置也会关闭。阅读、准备阅读和应用后台期间保留提示，退出阅读并返回前台后才展示和计时。
- 点击「立即更新」后，将已选中的正式安装包交给系统 `DownloadManager` 下载到应用专属目录。仅在发布信息缺少安装包地址时再次请求 GitHub。任务编号持久保存，回到前台或重新启动时恢复状态。同版本复用等待中、下载中和可安装的任务，失败或文件缺失时可在设置中重试。
- 下载完成后核对 APK 的包名和版本，通过 `FileProvider` 把安装包交给系统安装器。阅读中、正在打开漫画或应用退到后台时延后到书库或设置可交互时再打开安装器。首次安装可能需要按系统提示授权，取消后可在设置中再次选择「安装更新」。更新成功后，清理应用专属目录中的安装包。旧版在公共目录中的已完成下载可通过原任务恢复。
