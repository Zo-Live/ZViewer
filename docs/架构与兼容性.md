# 架构与兼容性

## 分层

- `MainActivity`：单 Activity、Compose、边到边显示。
- `LibraryViewModel`：应用状态、目录授权、扫描 / 打开任务、错误映射、设置与阅读记录。
- `PreferenceStore`：SharedPreferences 保存 URI、书目 JSON、页码、收藏和设置。书目数据是可通过重新扫描恢复的索引。
- `BookRepository`：DocumentsContract 批量查询、后台解压、PDF 渲染、封面与页面缓存。
- `ImageLoader`：根据 PNG 数据块识别 APNG；AVIF 由 APNG4Android + libavif 解码；其余格式交给系统 ImageDecoder。
- `ZoomImageView`：通过 AndroidView 接入原生图片矩阵、双指缩放、双击及平移；未缩放时交由 Compose 列表 / Pager 处理翻页。
- `ui/`：Material 3 Scaffold、NavigationBar、Card、FilterChip、SegmentedButton、ModalBottomSheet、Slider 与 Dialog。

## 数据流程

用户选择目录 → SAF 持久读取授权 → 后台递归扫描 → 书目索引 → 按需生成封面 → 打开书籍 → 准备页面 → 解码当前 / 邻近可见页面 → 保存页码。

ZIP、RAR、7Z 使用 libarchive JNI，同一入口读取多种容器。压缩包首次打开将支持的图片流式写入私有缓存，成功后才写入完整清单；取消或失败会清理未完成目录。对于固实压缩包，这比每翻一页重新解压前面的数据更可预测，但首次打开大书需要等待。

封面独立生成：先读取目录找到自然排序第一张图，再解码这一张，不为了显示书库而完整展开每本压缩包。PDF 缓存一个本地副本，以满足 PdfRenderer 可寻址文件描述符的要求。

## 生命周期与性能

- I/O、解压、PDF 渲染和图片解码运行在 `Dispatchers.IO`；流式操作检查协程取消。
- 封面生成并行数为 2，同一本书的准备工作通过 Mutex 串行。
- 阅读器采用 LazyColumn 或 HorizontalPager；仅可见、且应用处于前台的动画播放；离屏或退出时停止。
- 静态图片设置目标尺寸和像素上限；大型 APNG / AVIF 使用包装 Drawable 传递目标边界，使动画库按需采样。
- 缓存以 URI 摘要、修改时间和文件大小为键。源文件变化后重新生成；启动及退出阅读器时按最近使用顺序回收旧页面缓存，目标约 1.5 GiB。
- 自动回收阈值不是硬磁盘配额；当前打开的书籍、PDF 渲染图和封面可能使总缓存暂时超出阈值。设置中可手动清理。

## 文件与隐私

正式 Manifest 不申请 INTERNET、外部存储读写或 MANAGE_EXTERNAL_STORAGE 权限。只读取用户授权的目录，不删除、移动或改写漫画原件。禁用备份与设备迁移，避免无效 URI 授权随应用数据迁移。

压缩包成员永远写入应用生成的序号文件名，不将成员路径直接拼接到输出目录。只接收常规图片文件，忽略隐藏文件、macOS 元数据和非图片条目，不提取符号链接。存在页数、递归深度、单页及总解压大小限制。

测试使用的文件提供器只存在于单独的 `androidTest` APK；不会出现在正式应用中。测试样本为工具生成的原创占位图，无用户漫画内容。

## 系统支持

最低 API 29，编译 / 目标 API 36。现代 ARM64 手机为主要目标；x86_64 用于模拟器。启用预测返回回调并显示跟手过渡；低版本系统使用相同返回逻辑。Android 16 强制边到边布局所需的状态栏、导航栏和手势区域均由 Compose Insets 处理。

正式包的 `libarchive-jni.so`、`libavif_android.so`、`libandroidx.graphics.path.so` 的 ARM64 与 x86_64 ELF LOAD 段需具有至少 16 KB 对齐，APK 也需通过 `zipalign -P 16` 检查。构建和验证命令见测试记录。
