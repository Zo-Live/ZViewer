# 架构与兼容性

## 分层

- `MainActivity`：单 Activity、Compose、边到边显示。
- `LibraryViewModel`：应用状态、目录授权、扫描 / 打开任务、错误映射、设置与阅读记录。
- `PreferenceStore`：SharedPreferences 保存 URI、书目 JSON、页码、收藏、设置和日志选项。书目数据是可通过重新扫描恢复的索引。
- `DiagnosticLog`：可选的诊断日志。开启后把应用启动与设备信息、生命周期、书库扫描 / 打开、视频准备 / 缓冲 / 就绪 / 结束、播放开关、视频与 Surface 尺寸、首帧渲染、Surface 所有权交接、播放门槛判定、播放器池、封面抽帧耗时和未捕获异常追加到每个进程一个的 `zviewer-日期-时间.log`。默认写入应用专属外部目录（无需权限）；也可以在设置里通过 SAF 选择一个目录（例如 Download），应用只持有该目录的持久读写授权，不使用「所有文件访问」权限。日志写入在 IO 协程中串行执行，崩溃处理器同步刷盘；目录不可写时回退默认目录。
- `BookRepository`：DocumentsContract 批量查询、后台解压、PDF 渲染、视频文件缓存、封面与页面缓存。
- `ReadingCache`：统一统计与回收阅读文件、封面及视频首帧；按最近使用时间淘汰，通过引用计数保护会话与进行中的 I/O。
- `ImageLoader`：根据 PNG 数据块识别 APNG；AVIF 由 APNG4Android + libavif 解码；其余格式交给系统 ImageDecoder。
- `ZoomImageView`：通过 AndroidView 接入原生图片矩阵、双指缩放、双击及平移；未缩放时交由 Compose 列表 / Pager 处理翻页。
- `ReaderPaging`：将 Compose 列表 / Pager 的虚拟位置映射到真实页码，循环模式从重复页序的中部开始；首尾本身就是相邻项目，无边缘甩动后的突然跳页。重复页只按需创建，可见动画仍按虚拟位置管理。
- `VideoReader`：纯视频与混合内容统一使用 Pager 切换。播放器按“停靠页 + 左右相邻页”预建（最多三个），相邻视频在离屏时就把保存位置的首帧渲染到自己的 TextureView，滑动进入时画面已经就绪；播放器在页面仍处于 Pager 组合窗口期间不会被回收，因此“拖到一半再拉回”、连续来回切换时不会反复销毁 / 重建 Surface 而闪屏，也避免了循环模式下的重复虚拟项各自创建播放器。非相邻页只显示 `MediaMetadataRetriever` 抽帧并缓存的封面；会话级封面缓存只保留最近几页，避免长视频书占用过多内存。所有视频页共享同一个 `AndroidView` 结构：没有播放器时只显示封面，有播放器时挂到同一个视图上，不在“封面页 / 播放器页”之间切换视图结构。滑动是跟手的，拖动期间当前视频继续播放，停靠后才把播放移交给新视频；不再需要播放器的播放器释放并保存进度。每个播放器只允许一个 `ownerView` 持有输出 Surface，交接时先解除旧视图再绑定新视图，旧视图或临时重复视图释放时不会清掉当前 Surface，并会回退到仍停靠的活动视图；页面激活状态变化时重新确认所有权。播放门槛同时要求 owner 视图的 TextureView Surface 可用，Surface 丢失时暂停、恢复后继续。Media3 PlayerView 的黑色快门被设为透明，播放器尚未渲染首帧时会透出下方缓存的封面；封面永远垫在视频下方，由不透明的视频画面自然覆盖，不在首帧回调时切换可见性；进度圈只在停靠页且首帧尚未渲染时显示，避免预载 / 拖动页面闪现。封面首次抽帧失败时会在稍后重试一次。`repeatMode` 只由“单个视频循环 / 循环模式”设置决定，不随滚动 / 切换变化：ExoPlayer 在临近片尾时切换循环模式会重新初始化解码器输出（视频尺寸归零、画面重新渲染首帧）而闪屏；过渡期间播完的情况由 `onEnded` 回调从头重播处理。视频播完自动前进后再次返回该视频会从头重播，用户手动暂停的选择不受影响。切换及退出保存毫秒级进度，退到后台暂停，返回前台保留用户的暂停选择。
- `ZoomVideoView`：Android 开源框架 GestureDetector / ScaleGestureDetector 识别单击、双击、缩放和平移；未放大时把手势交给外层 Pager，由 Pager 提供跟手的翻页过渡（AndroidView 与 Compose 手势共存），放大或双指操作时请求父级不拦截手势以平移画面。Media3 PlayerView 使用 TextureView 和 FIT 等比布局，播放器视图下方叠加首帧封面 ImageView，切换时重置缩放。
- `ui/`：Material 3 Scaffold、NavigationBar、Card、FilterChip、SegmentedButton、ModalBottomSheet、Slider 与 Dialog。
- `LibraryScreen`：书库、收藏、最近阅读共用封面与收藏管理状态。`show_favorite_icon` 默认开启并由 SharedPreferences 保存；管理状态通过 `rememberSaveable` 保存，跨标签和配置重建保留。封面长按进入管理，显示收藏按钮的条件为「设置开启或正在管理」，管理时封面单击复用 `toggleFavorite`。管理状态的返回处理优先于收起搜索；退出按钮、设置、刷新与切换目录清除管理状态，搜索、筛选、排序不清除。

## 页面导航

书库导航由 `HorizontalPager` 承载书库、收藏和最近阅读三个页面，底部导航与 `currentPage` 同步，点击标签使用 `animateScrollToPage`，横向手势由 Pager 与纵向封面网格协调；空结果与未授权目录时同样可以切页。各页独立保存网格位置，搜索、筛选、排序及收藏管理状态由外层共用。

共用搜索栏使用 `AnimatedVisibility` 从顶部展开，280 ms 内轻微下滑并淡入，标题、筛选与封面区域随占用高度平滑下移；关闭时以 220 ms 向上收起并淡出，内容同步回到原位。高度与位移动画采用 `FastOutSlowInEasing`，支持动画中途反向切换，系统关闭动画时直接完成状态切换。关闭搜索仍清空关键词，切页、阅读与设置返回保留原有搜索状态及网格位置。

设置导航使用共享进度驱动的横向过渡：点击设置或返回时以 360 ms 的 `FastOutSlowInEasing` 动画推进，设置页从右侧进入，书库页面同步左移并从中心等比缩小到 80%；设置页右滑时直接跟随手指移动，两层内容按同一进度变换，松手后拖动距离达到 96 dp 就继续退出，否则回弹。背景使用当前主题背景色填充，竖向滚动和控件点击保持原行为。`rememberSaveableStateHolder` 保留离场页面的标签、搜索、筛选、排序与网格状态，支持配置重建及阅读后返回。过渡期间拦截触摸，离场内容移出无障碍操作树，设置的返回处理优先于书库的搜索 / 收藏管理返回处理，系统返回可中断进入动画。

## 数据流程

用户选择目录 → SAF 持久读取授权 → 后台递归扫描 → 书目索引 → 按需生成封面 → 打开书籍 → 准备页面 → 解码当前 / 邻近可见页面或创建当前视频播放器 → 保存页码和视频位置。

ZIP、RAR、7Z 使用 libarchive JNI，同一入口读取多种容器。Android 的 C locale 无法把带 UTF-8 标志的条目文件名转换为当前 locale，libarchive 会抛出 `ARCHIVE_WARN` 并中断读取，中文名压缩包因此被误判为损坏；打开归档前通过 libarchive-android 的 `Archive.setCharset` 把当前字符集覆盖为 UTF-8，使中文名条目可以正常读取。压缩包首次打开将支持的图片和视频流式写入私有缓存，成功后才写入完整清单；完整读取后只要发现 PDF，就提示先解压，无论是否同时存在图片或视频；取消或失败会清理未完成目录。对于固实压缩包，这比每翻一页重新解压前面的数据更可预测，但首次打开大书需要等待。

视频文件夹使用 `video-folder` 书籍类型，视频压缩包首次打开时也会把视频成员顺序解压到私有临时目录，再交给 Media3 播放。图片和视频在同一个文件夹或压缩包内时作为混合内容打开，按自然排序并跟随阅读方向设置（垂直翻页或水平翻页），按当前页类型显示图片或视频控制。支持的扩展名包括 MP4、M4V、MKV、WebM、AVI、MOV、3GP、3G2、MPG、MPEG、TS、MTS、M2TS、FLV、WMV、OGV、VOB、RM 与 RMVB，实际编码能力由设备 Media3/系统解码器决定。

封面独立生成：先读取目录找到自然排序第一个媒体，图片解码首图，视频使用 Android 开源框架的 MediaMetadataRetriever 抽取首个视频的帧，按比例缩小到 1000 × 1000 范围并缓存 JPEG。视频文件夹直接读取 SAF URI；视频压缩包只提取首个视频成员到临时文件，生成封面后删除，保留单视频 4 GiB 上限。生成失败时书库保留占位图；不为了封面而完整展开整本压缩包。PDF 封面优先使用已有阅读副本或原始 SAF 可寻址描述符；遇到管道等不可寻址来源才临时复制，生成封面后立即删除。正式阅读 PDF 仍缓存本地副本和按需渲染页，保证翻页稳定；渲染页缓存键使用实际限制后的宽度（480–2560），避免 3000 / 3200 等请求重复保存相同 2560 宽度的页面。

## 生命周期与性能

- I/O、解压、PDF 渲染和图片解码运行在 `Dispatchers.IO`；流式操作检查协程取消。
- 封面生成并行数为 2，同一本书的准备和封面生成分别通过 Mutex 串行；同一页面的文件缓存也串行写入，避免循环中多个可见副本争用临时文件。
- 图片阅读器采用 LazyColumn 或 HorizontalPager；循环只增加虚拟项目数，不复制媒体文件，记录的页码始终为真实页码。水平翻页预备前后各一页以便自然滑入；仅当前页的动画播放，垂直模式则播放可见动画；离屏、退到后台或退出时停止。
- 静态图片设置目标尺寸和像素上限；大型 APNG / AVIF 使用包装 Drawable 传递目标边界，使动画库按需采样。
- 缓存以 URI 摘要、修改时间和文件大小为键。源文件变化后重新生成；`books/` 与 `covers/`（含 `frames/` 和写入中的临时文件）使用与设置页一致的统计口径，合计达到 1536 MiB 时按最近使用时间回收到尽量不超过 1024 MiB。删除失败时按实际剩余大小核算，不虚报释放空间。
- 启动、退出阅读立即检查；打开完成、封面 / 页面 / 首帧处理完成、每个解压成员完成及单文件写入每跨过 16 MiB 均请求后台检查，通过合并通道与 500 ms 间隔合并连续请求。遍历和删除只在 IO 线程执行。
- `open()` 从准备开始保留书籍引用，成功后交给 `BookSession`；退出时由 `close(session)` 释放，失败与取消也会释放。封面解码、页面写入及视频抽帧使用短期引用；同一把锁协调引用获取与淘汰，避免回收正在使用或尚未写完的文件。仓库随 ViewModel 清理时停止后台任务。
- 自动回收阈值不是硬磁盘配额；若受保护的一本书已超过阈值，先清理其他闲置内容，保留当前书至退出后再回收。整本解压、原图质量、相邻页预载和播放器池保持不变；不以反复解压或有损重编码换取空间。设置中可双击「清理阅读缓存」手动删除闲置临时文件和封面。
- 视频按选定的垂直或水平方向平滑切换，混合内容同样跟随该设置；Pager 原生拖动提供跟手过渡，拖动与切换动画期间当前视频继续播放，停靠后才把播放移交给新视频。停靠页与左右相邻页各持有一个预载播放器（最多三个），相邻视频在离屏时已渲染好保存位置的首帧，拖动进入不需要临时创建 / 销毁 Surface，因此不会闪屏；更远的页面（包括循环模式下的重复虚拟项）只显示缓存的抽帧封面，避免多个解码器 / Surface 同时存在。播放器页的黑色快门设为透明，首帧渲染前透出封面；进度圈只在停靠页且首帧尚未渲染时显示。`repeatMode` 不随滚动 / 切换切换（临近片尾改循环模式会重置解码器输出而闪屏），过渡期间播完由 `onEnded` 从头重播。视频文件夹直接交给 Media3 读取 SAF URI，压缩包使用已解压的文件。播放结束自动进入下一段，设置可改为单段循环或仅预览。每段视频单独保存播放位置，完成播放后归零；书籍页码只由翻页更新，保存上一个视频的位置不会回写当前页码。
- 视频的双击只负责缩放；单击同步显示 / 隐藏底部工具栏和播放进度条。进度条左侧是播放 / 暂停按钮，上方显示当前时间与全长；拖动显示目标时间，松手提交定位，不添加暗色覆盖层。后台暂停不重新读取旧播放位置，退出释放播放器。

## 文件与隐私

正式 Manifest 不申请 INTERNET、外部存储读写或 MANAGE_EXTERNAL_STORAGE 权限。只读取用户授权的目录，不删除、移动或改写漫画原件。禁用备份与设备迁移，避免无效 URI 授权随应用数据迁移。

压缩包成员永远写入应用生成的序号文件名，不将成员路径直接拼接到输出目录。只接收常规图片和视频文件，忽略隐藏文件、macOS 元数据和非媒体条目，不提取符号链接。存在页数、递归深度、单页及总解压大小限制。

阅读进度按书籍 URI 保存；视频另按书籍和视频序号保存播放位置；设置、收藏、最近阅读持久化；缓存可清理且不影响原文件。设置中的“清除阅读记录”和“清理阅读缓存”均为双击执行；“清除阅读记录”移除所有页码和视频位置，“清理阅读缓存”只删除临时解压文件和封面。

测试使用的文件提供器只存在于单独的 `androidTest` APK；不会出现在正式应用中。测试样本为工具生成的原创占位图，无用户漫画内容。

## 系统支持

最低 API 29，编译 / 目标 API 36。现代 ARM64 手机为主要目标；x86_64 用于模拟器。启用预测返回回调并显示跟手过渡；低版本系统使用相同返回逻辑。Android 16 强制边到边布局所需的状态栏、导航栏和手势区域均由 Compose Insets 处理。

正式包的 `libarchive-jni.so`、`libavif_android.so`、`libandroidx.graphics.path.so` 的 ARM64 与 x86_64 ELF LOAD 段需具有至少 16 KB 对齐，APK 也需通过 `zipalign -P 16` 检查。构建和验证命令见测试记录。
