# 架构与兼容性

## 分层

- `MainActivity`：单 Activity、Compose、边到边显示。
- `LibraryViewModel`：应用状态、目录授权、扫描 / 打开任务、错误映射、设置与阅读记录。
- `PreferenceStore`：SharedPreferences 保存 URI、书目 JSON、页码、收藏、设置和日志选项。书目数据是可通过重新扫描恢复的索引。
- `DiagnosticLog` 与 `LogScreen` 负责本地诊断记录、只读查看和日志管理。
- `BookRepository`：DocumentsContract 批量查询、后台解压、PDF 渲染、视频文件缓存、封面与页面缓存。
- `PdfDocument` / `PdfReaderPages` 管理 PDF 会话、可见页优先级与相邻页预渲染。
- `ReadingCache`：统一统计与回收阅读文件、封面及视频首帧；按最近使用时间淘汰，通过引用计数保护会话与进行中的 I/O。
- `ImageLoader`：根据 PNG 数据块识别 APNG；AVIF 由 APNG4Android + libavif 解码；其余格式交给系统 ImageDecoder。
- `ZoomImageView`：通过 AndroidView 接入原生图片矩阵、双指缩放、双击及平移；未缩放时交由 Compose 列表 / Pager 处理翻页。
- `ReaderPaging`：将 Compose 列表 / Pager 的虚拟位置映射到真实页码，循环模式从重复页序的中部开始；首尾本身就是相邻项目，无边缘甩动后的突然跳页。重复页只按需创建，可见动画仍按虚拟位置管理。
- `VideoReader`：纯视频与混合内容统一使用 Pager。停靠页和前后相邻页预建播放器（最多三个），相邻视频提前渲染保存位置的首帧。切换阅读方向时，两个 Pager 复用当前页和预载页的内容，视频视图在移动时保留已绑定的 SurfaceTexture。每个虚拟项独立管理输出 Surface，离开预载范围时释放播放器并保存位置。同一播放器只有一个视图持有输出 Surface，转移时先解绑旧视图，临时视图释放后可由仍停靠的活动视图接管。Surface 可用时才播放。
- 视频页在同一个 `AndroidView` 内显示封面和播放器。封面覆盖 TextureView，等当前 Surface 输出首帧且等比布局就绪后撤下，书库开场和进度条预览也等待同一条件。缺少封面且停靠页仍在准备首帧时显示进度圈。会话级封面缓存保留最近几页，首次抽帧失败时稍后重试一次。
- `ZoomVideoView`：Android 开源框架 GestureDetector / ScaleGestureDetector 识别单击、双击、缩放和平移；未放大时把手势交给外层 Pager，由 Pager 提供跟手的翻页过渡（AndroidView 与 Compose 手势共存），放大或双指操作时请求父级不拦截手势以平移画面。Media3 PlayerView 使用 TextureView 和 FIT 等比布局，视频与首帧封面的缩放、平移均裁剪到本页边界。
- `ui/`：Material 3 Scaffold、NavigationBar、Card、FilterChip、DropdownMenu、ModalBottomSheet、Slider 与 Dialog。
- `LibraryScreen`：书库、收藏、最近阅读共用封面与收藏管理状态。`show_favorite_icon` 默认开启并由 SharedPreferences 保存。管理状态通过 `rememberSaveable` 保存，跨标签和配置重建保留。长按任意封面或其收藏按钮可进入或退出管理。显示收藏按钮的条件为「设置开启或正在管理」。收藏按钮保留独立的无障碍操作，管理时与封面单击共用收藏切换。管理状态的返回处理优先于收起搜索。退出按钮、设置与刷新清除管理状态，搜索、筛选、排序保留管理状态。

## 页面导航

书库导航由 `HorizontalPager` 承载书库、收藏和最近阅读三个页面。底部导航与 `currentPage` 同步，点击标签通过 `requestScrollToPage` 直接切页，横向手势保留跟手的滑动过渡，由 Pager 与纵向封面网格协调。空结果与未授权目录时同样可以切页。各页独立保存网格位置，搜索、筛选、排序及收藏管理状态由外层共用。当前网格离开顶部后，回顶按钮从右下方浮出，点击后平滑滚回顶部。回顶和退出收藏管理按钮均为圆形。收藏管理的退出按钮在顶部占据右下角，回顶按钮出现时向左移。点击回顶后，两枚按钮随最后一段滚动同步移动，列表到顶时回顶按钮已消失，退出按钮已移回右下角。已授权书库的目录入口位于「设置 → 书库与存储」。

共用搜索栏使用 `AnimatedVisibility` 从顶部展开，280 ms 内轻微下滑并淡入，标题、筛选与封面区域随占用高度平滑下移；关闭时以 220 ms 向上收起并淡出，内容同步回到原位。高度与位移动画采用 `FastOutSlowInEasing`，支持动画中途反向切换，系统关闭动画时直接完成状态切换。关闭搜索仍清空关键词，切页、阅读与设置返回保留原有搜索状态及网格位置。

阅读状态筛选在独立的一行内横向滚动，两侧留白与页头的 24 dp 内容边距对齐。某侧还有内容时，筛选标签在到达对应的留白前逐渐变透明。筛选行先按页边距裁剪并绘制淡出，再对绘制结果施加横向拉伸。所有筛选项可见时也会响应边界拖动，拉伸幅度随拖动距离逐渐减缓，并限制在留白内以保留标签轮廓。松手后通过弹簧动画恢复原位。分页手势从行外触发。空状态书本图标以三个标签共用的分页视口中点定位，标题和说明按应用语言分行。窗口高度有限时，空状态从筛选区下方开始，说明区域可滚动。

设置首页按顺序列出外观、偏好、阅读、书库与存储、诊断、安全与隐私、应用七个入口，各自进入独立页面。书库、设置首页、设置子页、日志列表和日志详情共用横向过渡，日志列表的上一级是诊断。打开子页时，子页从右侧进入，父页同步左移并从中心缩小到 80%。完整过渡使用 `FastOutSlowInEasing`，适中为 360 ms，增强为 216 ms。`rememberSaveableStateHolder` 保存书库标签、搜索、筛选、排序和网格状态，也保存父级设置页的滚动位置。过渡期间拦截触摸，离场内容移出无障碍操作树，系统返回可中断进入动画。

页内右滑在右移达到 16 dp 和系统触控阈值两者中的较大值，且右移至少为纵向位移的 1.5 倍时开始跟手。纵向位移先达到系统触控阈值且右移比例不足，或向左位移先达到阈值时，本次触摸保持原有手势，直到松手。页内右滑带动页面移动达到 96 dp 后松手返回上一级，距离较短时回弹。页内右滑和系统预测返回的收尾动画时长均按剩余位移和当前档位计算。

## 数据流程

「设置 → 外观」依次提供应用主题、每行封面数、动态取色和主题颜色。「设置 → 偏好」依次显示语言、动画速度、触感反馈及书库封面显示选项。应用独立保存语言代码，默认简体中文。切换语言时重建 Activity 以加载对应的 Android 字符串资源，并恢复设置页及书库导航状态。应用主题、语言、动画速度、每行封面数和阅读模式共用菜单控件，整行可点击，无障碍树提供菜单按钮的名称、当前值和展开状态，以及各选项的选中状态。阅读器快捷设置和书库排序也使用相同的菜单定位。菜单与触发控件的末端对齐，以完整控件的上下边界作为锚点，由 Material 3 `DropdownMenu` 决定弹出方向和窗口边距。

「动画速度」默认「适中」。选择「增强」后，页面横向过渡、搜索栏展开收起、对话框、阅读器快捷设置和阅读缩放采用较短的时长，书库与阅读器翻页停靠及工具栏动画更快结束。页面拖动和双指缩放继续跟随手势。设置页进退过渡从 360 ms 缩短至 216 ms，双击及工具栏缩放从 220 ms 缩短至 132 ms。阅读器快捷设置保留 Material 3 底部面板的拖动和返回手势，增强档在系统动画缩放的基础上使用 0.6 倍时长。

Material 3 下拉菜单、底栏选中指示、开关、圆形和线形加载指示，以及书库回顶滚动均跟随动画速度。增强档将这些组件的动画时长缩短至 0.6 倍，并叠加系统动画倍率。视频和动态图片按各自的播放时序显示。

「触感反馈」默认开启，并遵循 Android 的触感反馈设置。开启该开关时轻振一次，关闭时无振动。收藏与开关使用系统的开启和关闭触感，选择新菜单项时使用刻度触感。进入收藏管理使用长按确认，所有退出途径使用较轻的关闭触感。清理项在每次有效点击松手时轻振，双击共振动两次并执行一次清理。自动清理阈值滑条在 256 MiB 的普通刻度使用轻振，到达最小值或最大值时使用边界反馈。关闭时停止应用内触感反馈。

自定义主题颜色弹窗的色轮和 RGB 滑条保留连续取色。外圈每 30°、RGB 滑条每 32 个色阶设一个触感刻度。正方形内的饱和度有五至七档，明度有七档（均含两端），暗部的横纵刻度都更密。色相经过 90° 和 270° 的冷暖分界、饱和度进出约 6% 的无彩色区时使用单独的过渡反馈，Android 10–13 使用系统虚拟按键触感。正方形四边和 RGB 滑条两端使用边界反馈，边缘附近的小幅抖动会被过滤。点按控件或松手确认颜色时播放选中反馈。外观页切换到新的预设色块时播放一次选中反馈。点击「应用」时，最终 RGB 与弹窗初始值不同才保存并播放确认反馈。

「动态取色」默认关闭，开关状态与手动主题色独立保存。Android 12 及以上开启后，应用使用系统莫奈配色，并按「应用主题」选择浅色或深色方案。预设颜色始终可选。开启时，只有与当前系统方案主色的色值完全相同的预设会打勾。手动关闭开关会恢复上次保存的手动主题色。点击预设会将该颜色保存为手动主题色。动态取色开启时，选择与系统主色相同的预设会保持开启，选择其他预设会关闭开关。动态取色关闭时，选择任意预设都保持关闭。Android 10 和 11 直接隐藏该开关，使用手动主题色。

「主题颜色」右侧的调色盘打开自定义对话框。首行居中预览当前亮暗模式的主色、次色、主色容器和界面背景。开启动态取色时，四张色卡直接使用系统方案，色轮、RGB 滑条和 HEX 输入使用系统方案的主色作为初始值。色轮外环选择色相，内区调整饱和度和明度，所有控件及预览即时联动。调整后的颜色按手动配色算法预览，调回系统主色时重新显示系统方案。输入未满六位时保留最近的有效预览，补全后即可应用。动态取色开启时，点击「应用」且最终色值有变化才会保存手动主题色并关闭动态取色。点击「取消」、关闭对话框或以原色应用会保留当前配色。调色盘、「关于 ZViewer」和「开源许可」共用上滑淡入、下滑淡出的窗口动画。「开源许可」预留正文滚动区域，载入许可文本时对话框位置保持稳定。

调色盘由浮动窗口统一处理系统栏和软键盘占用的空间，进场时以同一个可用区域居中。空间不足时色卡、色轮和 RGB 滑条可滚动，HEX 输入和底部按钮保留在可视区域。

设置子页直接在页面背景上排列设置行，两侧各留 24 dp。顶栏标题居中，长标题换行时顶栏随之增高。设置菜单行的当前值向下拉箭头对齐，换行时各行保持右对齐。说明统一使用 Material 3 的 `bodySmall`，宽度上限为 480 dp。带末端内容的设置行至少为数值或控件预留 52 dp，文字与该区域之间保留 16 dp 间距。阅读器快捷设置沿用相同的行布局，可在空间不足时滚动。「开源许可」的导语随应用语言切换，`open_source_notices.txt` 由 `tools/collect_licenses.py` 收集许可原文。

阅读设置在「阅读模式」后按顺序显示「从右向左翻页」「阅读时屏幕常亮」「使用音量键翻页」「双击以放缩」「深色阅读背景」。「从右向左翻页」仅在水平翻页时显示，默认关闭，切换阅读模式时保留选择。「使用音量键翻页」默认关闭，开启后阅读时音量减键前往下一页、音量加键返回上一页。视频翻页动画期间连按音量键会从仍在前往的目标累计翻页。「双击以放缩」默认开启，控制漫画图片、PDF 页和视频的双击缩放。

用户选择目录 → SAF 持久读取授权 → 后台递归扫描 → 书目索引 → 按需生成封面 → 打开书籍 → 准备页面 → 解码当前 / 邻近可见页面或创建当前视频播放器 → 保存页码和视频位置。

书库名称、文件夹媒体、压缩包成员与封面选取共用 `NaturalOrder`。数字、拉丁字母、中文依次排列，数字按数值比较，中文使用词组字典确定多音字读音。含假名的文件名用日语校对规则处理相邻假名和汉字，纯汉字使用拼音规则。压缩包缓存清单保留原始文件名，每次打开按当前规则排列。升级后首次打开未变更的书籍时，将旧阅读页码和视频进度映射到同一文件。

ZIP、RAR、7Z 使用 libarchive JNI，同一入口读取多种容器。Android 的 C locale 无法把带 UTF-8 标志的条目文件名转换为当前 locale，libarchive 会抛出 `ARCHIVE_WARN` 并中断读取，中文名压缩包因此被误判为损坏；打开归档前通过 libarchive-android 的 `Archive.setCharset` 把当前字符集覆盖为 UTF-8，使中文名条目可以正常读取。压缩包首次打开将支持的图片和视频流式写入私有缓存，成功后才写入完整清单；完整读取后只要发现 PDF，就提示先解压，无论是否同时存在图片或视频；取消或失败会清理未完成目录。对于固实压缩包，这比每翻一页重新解压前面的数据更可预测，但首次打开大书需要等待。

视频文件夹使用 `video-folder` 书籍类型，视频压缩包首次打开时也会把视频成员顺序解压到应用的阅读缓存，再交给 Media3 播放。图片和视频在同一个文件夹或压缩包内时作为混合内容打开，按自然排序并跟随阅读方向设置（垂直翻页或水平翻页），按当前页类型显示图片或视频控制。支持的扩展名包括 MP4、M4V、MKV、WebM、AVI、MOV、3GP、3G2、MPG、MPEG、MPE、TS、MTS、M2TS、MPEGTS、FLV、WMV、OGV、VOB、RM 与 RMVB，实际编码能力由设备 Media3/系统解码器决定。

封面独立生成，选用自然排序的首个媒体。图片封面以 1000 像素为宽度上限并限制总像素数，视频封面使用 Android 的 MediaMetadataRetriever 抽帧，缩放到 1000 × 1000 范围内，结果以 JPEG 缓存。视频文件夹直接读取 SAF URI。压缩包先遍历成员选定首个媒体，再次打开归档并只将该成员提取到临时文件，生成封面后删除。生成或解码失败时，书库显示占位图。PDF 封面优先使用已有阅读副本或原始 SAF 可寻址描述符。遇到管道等不可寻址来源才临时复制，生成封面后立即删除。

打开 PDF 时优先使用已有副本或可寻址的 SAF 描述符。不可寻址的来源会流式复制到缓存。每次阅读复用一个系统 `PdfRenderer`，退出时释放。垂直连续与水平翻页模式均优先渲染当前可见页，并预渲染视口前后各一页。翻页和跳页会更新渲染优先级，离开预载范围的位图交回系统回收。原图位图直接显示，渲染宽度限制为 480–2560 像素，并按应用内存额度限制单页像素数。

## 生命周期与性能

- I/O、解压、PDF 渲染、图片解码及书目 JSON 读写中的解析和编码运行在 `Dispatchers.IO`。书库按名称排序时复用索引顺序，搜索与筛选保留该顺序。扫描提交书目后才清理旧缓存。切换目录会取消旧扫描与打开任务，只有当前打开任务能更新准备提示或交付阅读会话。
- 封面生成最多同时处理两本，同一本书的准备和封面生成分别通过 Mutex 串行。书库卡片按显示尺寸解码缩略图，最多同时解码两张，并使用 24 MiB 内存缓存复用最近加载的缩略图。同一页面的文件缓存也串行写入，避免循环中多个可见副本争用临时文件。
- 图片阅读器采用 LazyColumn 或 HorizontalPager；循环只增加虚拟项目数，不复制媒体文件，记录的页码始终为真实页码。水平翻页预备前后各一页以便自然滑入；仅当前页的动画播放，垂直模式则播放可见动画；离屏、退到后台或退出时停止。
- 纯图片阅读器打开时先加载当前页，当前页加载完成或报错后才启动相邻页加载。图片解码在后台最多同时执行两项。静态图片将视口宽度的两倍用作解码目标，GIF、动态 WebP 和 APNG 以视口宽度为目标并限制解码像素数。APNG 在动画库分配帧缓冲前确定采样倍数，避免视图设置边界后重复解析。动画随页面可见性和视图附着状态启停，有限次数动画自然播放完后保持末帧。
- 压缩包与 PDF 缓存以 URI 摘要、修改时间和文件大小为键；图片 / 视频文件夹额外保存按 URI 排序的成员签名，覆盖每个媒体的 URI、名称、修改时间与大小，避免改名或非最新成员变化被最大时间 / 总大小掩盖。签名随书目索引持久化。每次完整扫描成功后，比较上次索引，删除变化或移除书目的旧缓存。开启「仅保留当前书库缓存」后会扫描当前书库，并在每次扫描成功后清理未纳入当前书库的临时文件、完整封面和视频首帧。扫描失败或取消时保留缓存，仍被阅读或生成任务引用的旧缓存延迟到最后一个引用释放后删除。
- 完整书库封面与视频首帧保存在 `files/covers/`（首帧位于 `frames/`），不因未使用时长、重新启动、Android 回收缓存目录或应用容量自动清理而删除。旧版 `cache/covers/` 中已完成的 JPEG 在 IO 线程迁移并复用；临时源文件留在 `cache/covers/`。首次为旧文件夹索引补充成员签名时，原有大小、修改时间和类型一致即沿用旧封面，建立签名基线。
- `cache/books/`、`cache/covers/` 与 `files/covers/`（含首帧和写入中的临时文件）全部计入设置页缓存大小。合计达到用户设置的清理阈值时，只按最近使用时间回收闲置阅读文件和未完成的临时文件，尽量降至阈值的三分之二；完整封面和首帧始终保留。删除失败时按实际剩余大小核算，不虚报释放空间。
- 「书库与存储」中的「仅保留当前书库缓存」和「自动补全封面」均默认关闭。开启补全、启动或切换书库后的扫描完成时，`LibraryViewModel` 检查整套书库的封面缓存。后台检查 JPEG 首尾标记并重建缺失、为空或截断的封面。书库解码遇到损坏的缓存时，立即重建并重试一次。任务在设置页、阅读页和应用退到后台时继续运行，每次只生成一本，给可见卡片留出生成容量。切换书库或关闭开关时取消旧任务，单本生成失败后继续处理其余书目。系统结束进程后，下次启动重新检查并复用完整封面。
- 「清理封面」默认关闭，双击清理时保留完整封面和视频首帧，开启后同时清理，缓存项说明才追加「和封面」。开启自动补全时，清理完成即开始重新生成缺失的书库封面，阅读页的视频首帧仍按需生成。`cache_limit_mib` 默认 1536 MiB，范围 256–8192 MiB、步长 256 MiB；拖动时显示当前容量，松手保存并立即检查回收，更新设置页缓存统计。每次自动回收从持久设置读取上限，重启后继续生效；按容量自动回收始终保留完整封面。
- 阈值滑条后是「移除后台时清理阅读缓存」，「清除阅读记录」后是「移除后台时清除阅读记录」。两个开关默认关闭。Android 最近任务移除事件触发已开启的清理，缓存清理沿用「清理封面」设置。在 Android 11 及以上，系统提前结束进程时，在同次开机的下次启动核对旧任务卡片并补做清理。
- 启动、退出阅读立即检查；打开完成、封面 / 页面 / 首帧处理完成、每个解压成员完成及单文件写入每跨过 16 MiB 均请求后台检查，通过合并通道与 500 ms 间隔合并连续请求。遍历和删除只在 IO 线程执行。
- `open()` 从准备开始保留书籍引用，成功后交给 `BookSession`。退出、准备失败与取消均释放引用。封面解码、页面写入及视频抽帧使用短期引用。同一缓存目录的仓库共享引用计数，最近任务移除时仍在使用的文件会在最后一个引用释放后清理。容量统计和排序在引用计数锁外完成，删除前检查文件状态和当前引用。
- 自动回收阈值不是硬磁盘配额；完整封面或受保护的一本书已超过阈值时，先清理其他闲置临时内容，允许总量高于目标；当前书保留至退出后再回收，封面仍保留。整本解压、原图质量、相邻页预载和播放器池保持不变；不以反复解压或有损重编码换取空间。设置中可双击「清理阅读缓存」手动删除闲置临时文件，是否同时删除完整封面由「清理封面」开关决定。
- 视频按选定的垂直或水平方向平滑切换，混合内容同样跟随该设置。拖动与切换动画期间当前视频继续播放，停靠后才把播放移交给新视频。`repeatMode` 由单段循环和循环阅读设置决定，过渡期间播完由 `onEnded` 从头重播。视频文件夹直接交给 Media3 读取 SAF URI，压缩包使用已解压的文件。播放结束自动进入下一段，每段视频单独保存播放位置，完成播放后归零，返回已播完的视频时从头播放。手动暂停和退到后台会保留当前位置，返回前台保留用户的暂停选择。
- 双击和工具栏缩放在「适中」下使用 220 ms 动画，双击以触点为中心，工具栏以页面中心为基准。垂直连续模式按可见页中心到视口中心的距离定位，距离相同取上方页，且只向选中的虚拟项发送指令。连续页的画幅由原始宽高比决定，缩放和平移裁剪到页内。连续点击按上一次目标倍率计算，双指操作可接管当前倍率。单击同步显示或隐藏底部工具栏和进度条。
- 从书库打开到视频页时，在书库后方准备初始视频。停靠页输出首帧后切入阅读器并按设置开始播放，播放出错或等待满 3 秒时进入阅读器显示错误或加载状态。等待状态属于本次打开的书籍，活动阅读页重建时直接恢复。打开书籍超过 250 ms 才显示「准备阅读」对话框。
- 拖动页码进度条时，滑条和数字跟随手指。垂直连续模式按图片比例和页间距组成完整视口，再一起更换画面。循环模式在末页下方接续首页。目标页尚未就绪时，优先显示附近缓存的完整视口，否则保留上一组画面。缓存读取与源文件解码并行调度，各自合并待处理页码。
- 图片与动态图片首帧的预览目标宽度为视口的 45%，限制在 320–640 像素，单张最多 28 万像素。PDF 先复用阅读位图，按需补渲染宽 240–480 像素、最多 18 万像素的预览。每个会话最多缓存 24 MiB 预览位图。视频预览复用已有首帧或直接抽取低分辨率位图，磁盘预生成写入可回收的 WebP。播放器页面仍按需保存完整首帧。
- 打开长书后，空闲时先生成当前页附近的 WebP 预览，再每隔若干页生成一组覆盖视口的预览，最后逐页补齐。索引使用书籍缓存键和预览宽度，书籍内容变更后使用新缓存。每种预览宽度最多写入 96 MiB，与其他阅读缓存一起统计与清理。阅读滚动、拖动进度条及还原画质时暂停预生成。
- 按住进度条停下后，停止提交新的预览解码，优先加载目标页的正常阅读画质。慢拖停顿约 120 ms 开始加载，若最后一次位置更新跨过至少两页则等待约 250 ms。松手立即进入同一加载流程并保存目标页。连续模式等目标页就绪且其余可见页均已有缩略图或正常画质后撤下整屏预览。视频等停靠页播放器输出首帧并留出一帧合成时间后接替预览，松手后按设置播放。
- 拖动视频播放进度条时暂停播放，并启用 Media3 的拖动模式。每个界面帧最多提交一次最新位置，Media3 继续合并解码器尚未处理的定位请求并复用解码状态。松手退出拖动模式，补交尚未提交的最终位置并保存，恢复拖动前的播放或暂停状态。后台暂停保留当前播放位置，退出时释放播放器。
- 视频进度条上方右侧提供 0.5x、0.75x、1.0x、1.5x、2.0x 五档。视频页长按进入 2.0x，松手恢复 1.0x。长按后上滑并松手锁定 2.0x，锁定后长按下滑并松手恢复 1.0x。手势使用系统长按判定。锁定或解锁需要纵向位移大于横向位移的 1.5 倍，并达到 32 dp 和四倍系统触摸容差中的较大值。画面及留黑区域可识别手势，展开的工具栏截住触摸。新加载的视频默认 1.0x，Media3 用原有播放时钟协调音画，`PlaybackParameters` 让音频变速时保持原音高。[Media3 PlaybackParameters](https://developer.android.com/reference/androidx/media3/common/PlaybackParameters) · [Media3 播放时钟](https://github.com/androidx/media/blob/1.9.4/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/DefaultMediaClock.java)
- 「垂直连续」下默认开启「左右滑动调整视频播放进度」，「水平翻页」下显示「从右向左翻页」。视频横滑需超过两倍系统触摸容差，且横向位移大于纵向位移的 1.5 倍。向右前进、向左后退，一屏对应视频时长与 60 秒中的较短者。拖动复用视频预览定位，取消手势恢复起点，放大后的单指滑动用于平移画面。
- 视频和页码滑条使用触摸事件的单调时间戳。相邻页或相邻整秒的到达间隔达到 80 ms 时请求轻振，间隔更短或一次跨过多个刻度时跳过该次反馈。每次拖动到达任一端点时单独反馈，各端最多一次。AOSP SystemUI 的滑条按振动原语时长计算最小反馈间隔。本应用采用固定的 80 ms 下限，参考 crDroid SystemUI 连续滑条的轻振后备节奏，普通刻度每秒最多请求 12.5 次。倍速选档使用离散刻度反馈，锁定使用确认反馈，解锁使用较轻的阈值取消反馈，播放和暂停使用开关反馈。[AOSP SystemUI 滑条实现](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/packages/SystemUI/src/com/android/systemui/haptics/slider/SliderHapticFeedbackProvider.kt) · [crDroid SystemUI 滑条实现](https://github.com/crdroidandroid/android_frameworks_base/blob/16.0/packages/SystemUI/src/com/android/systemui/haptics/slider/SliderHapticFeedbackProvider.kt) · [Android 触感反馈指南](https://developer.android.com/develop/ui/views/haptics/haptics-principles)
- 倍速弹窗沿用 Material 3 下拉菜单的容器和文字配色，当前档位的勾选图标与设置菜单一样使用主题主色。菜单在按钮上方展开，以靠近按钮的底角为中心，从 80% 缩放至 100%，同时淡入。「适中」沿用 Material 3 的 120 ms 缩放和 30 ms 淡入时序，「增强」分别缩短至 72 ms 和 18 ms。两档都叠加系统动画倍率。

### 页码拖动的调度选择

拖动经过的页数可以超过屏幕刷新率，同一页的源文件读取、解码和纹理上传时间也随内容而变。逐个完成所有目标会累积滞后。这里采用请求合并、在途结果渐进显示和最终位置优先。Media3 的拖动模式使用一个在途定位和一个可覆盖的待处理定位。PDF.js 优先渲染可见区域，沿滚动方向预读，并复用已渲染页面生成缩略图。Android 的 `PdfRenderer` 每次只允许打开一页，离开低清预览时最多等待一项已进入系统的渲染。[Media3 定位实现](https://github.com/androidx/media/blob/1.9.4/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/ExoPlayerImplInternal.java) · [PDF.js 渲染队列](https://github.com/mozilla/pdf.js/blob/master/web/pdf_rendering_queue.js) · [PDF.js 缩略图](https://github.com/mozilla/pdf.js/blob/master/web/pdf_thumbnail_view.js) · [Android PdfRenderer](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer)

预生成使用与 Shaka Player 缩略图轨道相同的思路。把昂贵的解码提前，拖动时按位置查找独立的预览。首次打开时，已生成的覆盖范围取决于空闲时长、页面耗时和磁盘预算。未命中的目标页继续按需解码。[Shaka Player 缩略图实现](https://github.com/shaka-project/shaka-player/blob/main/lib/player.js)

## 文件与隐私

正式 Manifest 为 GitHub 更新申请 INTERNET 和 REQUEST_INSTALL_PACKAGES 权限。安装来源授权与安装确认均由 Android 处理。应用通过 SAF 读取用户授权的书库并保留漫画原件，诊断日志写入应用目录或拥有读写授权的 SAF 目录。应用无需全盘存储权限。禁用备份与设备迁移，避免无效 URI 授权随应用数据迁移。

- 「启动时验证」和「切换至后台后重新验证」独立启用，均需先设置系统屏幕锁定。Android 的 `BiometricPrompt` 决定可用的生物识别方式并提供屏幕锁定凭证入口。验证取消后，解锁页只显示应用图标和「进行验证」按钮。按钮使用当前主题的配色，图标以当前主题的深色为背景，保留白色 Z。后台计时使用单调时钟，间隔可选立即、15 秒、1 分钟或 5 分钟，默认 15 秒。界面仅在验证通过后恢复书库、设置或阅读页。
- 「模糊预览」会在最近任务列表中隐藏应用预览，开启后无法截屏或录屏。Android 13 及以上同时关闭最近任务截图。
- 「隐藏后台卡片」默认关闭。开启后，先将应用切换至后台，再打开最近任务列表，系统会隐藏 ZViewer 卡片。从应用内直接上滑并停留时，系统仍可能显示当前卡片。
- 「在系统相册中隐藏图片」在包含图片的书库目录中创建 `.nomedia`。当前书库只有读取权限时，通过系统目录选择器对同一目录补授写入权限。扫描会处理新增的图片集。关闭或切换书库时，应用清理自己创建的标记，已有标记予以保留。切换后会释放旧书库的专用授权，清理失败所需的授权保留至重试，明确选作日志目录的授权继续保留。旧书库失去授权或旧图片集离开扫描范围后，应用保留标记归属，目录重新可访问时可继续清理。写入权限提示对应当前书库的相册可见性操作。系统重新扫描媒体后，相册更新显示，建议重启设备。`.nomedia` 的作用范围包括该目录下的媒体和子目录。

压缩包成员永远写入应用生成的序号文件名，不将成员路径直接拼接到输出目录。只接收常规图片和视频文件，忽略隐藏文件、macOS 元数据和非媒体条目，不提取符号链接。存在页数、递归深度、单页及总解压大小限制。

每本书保存页码，图片和视频另以 SAF URI 或归档成员名生成的标识恢复阅读位置。原媒体找不到时，使用限制在新页数范围内的旧页码。视频播放位置按媒体标识保存，新插入的视频从头播放。旧版页码在首次打开时用作定位，旧版视频位置在页数一致时按当前页序迁移一次。设置、收藏和最近阅读均会持久化。设置中的“清除阅读记录”和“清理阅读缓存”均为双击执行。“清除阅读记录”移除所有页码和视频位置，“清理阅读缓存”删除临时解压文件，仅在开启“清理封面”后同时删除完整封面和视频首帧。

测试使用的文件提供器只存在于单独的 `androidTest` APK；不会出现在正式应用中。测试样本为工具生成的原创占位图，无用户漫画内容。

## 诊断日志

- 诊断默认关闭。开启后记录应用与设备信息、显示和资源用量、目录授权与设置、生命周期、扫描和打开耗时、阅读、缓存、媒体错误、更新和崩溃堆栈。每条记录包含时间、时区、级别、分类、进程、线程和运行时长。常规事件使用书目标识摘要并脱敏 URI。异常堆栈可能包含文件路径。
- 日志会话配置与常规写入在后台执行，队列最多 512 条。单条消息保留前 16,384 个字符，单文件达到约 2 MiB 时停止常规记录，崩溃时仍会尝试同步写入。默认目录保留最多 5 份日志。自行选择的 SAF 目录不可写时回退至默认目录，其中的历史日志由用户清理。
- 设置页可查看、复制或分享单份日志，也可通过系统文件选择器导出或双击清理。关闭采集后仍可管理已有日志。默认目录及曾明确选为日志目录且仍有读写授权的目录会进入列表，按文件名降序展示。升级时沿用现有的自选日志目录。旧版本未记录来源的历史目录需重新选为日志目录，文件仍留在原处。多份日志导出为所选目录中的一个 `ZViewer-logs-*.zip`，压缩包保留原始文件名，同名日志放入编号子目录。单份日志导出原文件，目标目录若就是日志源目录则导出为 ZIP。无日志时提示「当前无日志」，读写失败时提示「无法导出日志」，写入中断时尝试删除未完成的文件。清理后若诊断仍开启，下一条诊断事件会创建新日志。
- 日志详情使用 Android 原生手柄和浮动菜单。菜单按顺序显示 ContentCopy、SelectAll、Search、Translate、Share 五个 Material Symbols 图标，无障碍名称使用应用语言。超出内联分享长度上限的选区通过临时文本文件分享。搜索和翻译由 Android 解析默认应用，缺少兼容应用时显示提示。

## 系统支持

最低 API 29，编译 / 目标 API 36。现代 ARM64 手机为主要目标；x86_64 用于模拟器。启用预测返回回调并显示跟手过渡；低版本系统使用相同返回逻辑。Android 16 强制边到边布局所需的状态栏、导航栏和手势区域均由 Compose Insets 处理。

正式包的 `libarchive-jni.so`、`libavif_android.so`、`libandroidx.graphics.path.so` 的 ARM64 与 x86_64 ELF LOAD 段需具有至少 16 KB 对齐，APK 也需通过 `zipalign -P 16` 检查。构建和验证命令见测试记录。

## 测试样本

干净检出后，先运行 `python3 tools/generate_fixtures.py`，再在 Android Emulator 上运行 `./gradlew :app:connectedDebugAndroidTest`。样本生成需要 Python 的 Pillow（含 AVIF 支持）、pillow-heif、py7zr 和 ReportLab，以及 FFmpeg（含 libx264）、文泉驿正黑字体 `/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc` 和当前脚本指定的 RAR 命令 `/tmp/rar/rar`。主脚本会生成视频样本，输出到 `tools/fixtures/`，由仪器测试 APK 打包。

## 应用更新

- 「设置 → 应用」使用 Info 图标作为入口，子页依次提供「检查更新」（显示当前版本）、「启动时检查更新」（默认关闭）、「关于 ZViewer」和 GitHub 仓库入口。开关整行可操作，仓库链接优先交给 GitHub Mobile，否则交给 Android 的链接处理程序。
- `UpdateChecker` 在 IO 线程请求 `https://api.github.com/repos/Zo-Live/ZViewer/releases/latest`，仅接受正式版本，按主 / 次 / 修订号进行数值比较。只选择 `ZViewer-x.x.x-release.apk` 通用包，并校验 HTTPS、官方仓库路径与资源大小；草稿、预发布、非法 JSON 或标签不会被当成最新版本。
- 高于当前安装版本的正式发布才写入持久缓存。手动检查 60 秒内复用，启动检查 6 小时内复用，过期后通过 ETag / 304 重新验证。网络错误、HTTP 异常和无更新结果可立即再次请求。连接超时 5 秒、读取超时 8 秒、总请求截止 15 秒，响应最多 512 KiB。
- 启动只在 ViewModel 初始化时按设置检查，配置重建不重复检查；自动检查在发现新版本时提示，最新或失败时保持安静。手动检查使用行内进度指示，不弹进度对话框。
- 新版本使用确认弹窗。更新和日志操作的短提示统一使用 Android 系统 Toast。阅读、准备阅读和应用后台期间保留更新结果，恢复到前台可交互页面后再展示一次。
- 点击「立即更新」后，将已选中的正式安装包交给系统 `DownloadManager` 下载到应用专属目录。仅在发布信息缺少安装包地址时再次请求 GitHub。任务编号持久保存，回到前台或重新启动时恢复状态。同版本复用等待中、下载中和可安装的任务，失败或文件缺失时可在设置中重试。
- 下载完成后核对 APK 的包名和版本，通过 `FileProvider` 把安装包交给系统安装器。阅读中、正在打开漫画或应用退到后台时，延后到阅读器外的页面恢复交互后再打开安装器。首次安装可能需要按系统提示授权，取消后可在设置中再次选择「安装更新」。更新成功后，清理应用专属目录中的安装包。旧版在公共目录中的已完成下载可通过原任务恢复。
