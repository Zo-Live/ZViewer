# 架构与兼容性

## 分层

- `MainActivity`：单 Activity、Compose、边到边显示。
- `LibraryViewModel`：应用状态、目录授权、扫描 / 打开任务、错误映射、设置与阅读记录。
- `PreferenceStore`：SharedPreferences 保存 URI、书目 JSON、页码、收藏和设置。书目数据是可通过重新扫描恢复的索引。
- `BookRepository`：DocumentsContract 批量查询、后台解压、PDF 渲染、视频文件缓存、封面与页面缓存。
- `ImageLoader`：根据 PNG 数据块识别 APNG；AVIF 由 APNG4Android + libavif 解码；其余格式交给系统 ImageDecoder。
- `ZoomImageView`：通过 AndroidView 接入原生图片矩阵、双指缩放、双击及平移；未缩放时交由 Compose 列表 / Pager 处理翻页。
- `ReaderPaging`：将 Compose 列表 / Pager 的虚拟位置映射到真实页码，循环模式从重复页序的中部开始；首尾本身就是相邻项目，无边缘甩动后的突然跳页。重复页只按需创建，可见动画仍按虚拟位置管理。
- `VideoReader`：纯视频书在稳定状态使用单个 AndroidX Media3 ExoPlayer 和单个视图；混合内容的水平 Pager 为相邻视频维护播放器，图片页不创建播放器。滑动、工具栏按钮、序号跳转与自动续播统一切换当前媒体。翻页等待下一段首帧回调和等比布局后开始固定 240 ms 的滑入 / 滑出动画，过渡期间当前视频继续播放、下一视频保持暂停；加载失败时过渡到错误提示。稳定态与过渡态使用同一个容器和按播放状态标识的视图节点，避免重新创建 TextureView 造成黑屏；完成后只释放旧播放器。混合内容只允许已停靠且媒体已准备好的当前视频播放，不把离屏视频的首帧作为播放前置条件，避免从图片切入视频时因预加载播放器暂停而形成播放死锁；媒体准备不会清空已完成的视图就绪状态。混合内容保留已创建的播放器，视频播完自动前进后再返回该项时，重新激活已播完（`STATE_ENDED`）的播放器会回到开头并按预览设置恢复播放，用户手动暂停的选择不受影响。切换及退出保存毫秒级进度，退到后台暂停，返回前台保留用户的暂停选择。
- `ZoomVideoView`：Android 开源框架 GestureDetector / ScaleGestureDetector 识别单击、双击、缩放和平移；未放大时按选定方向识别翻页，一次手势最多切换一个视频。Media3 PlayerView 使用 TextureView 和 FIT 等比布局，尺寸由实际容器测量，切换时重置缩放。
- `ui/`：Material 3 Scaffold、NavigationBar、Card、FilterChip、SegmentedButton、ModalBottomSheet、Slider 与 Dialog。

## 数据流程

用户选择目录 → SAF 持久读取授权 → 后台递归扫描 → 书目索引 → 按需生成封面 → 打开书籍 → 准备页面 → 解码当前 / 邻近可见页面或创建当前视频播放器 → 保存页码和视频位置。

ZIP、RAR、7Z 使用 libarchive JNI，同一入口读取多种容器。Android 的 C locale 无法把带 UTF-8 标志的条目文件名转换为当前 locale，libarchive 会抛出 `ARCHIVE_WARN` 并中断读取，中文名压缩包因此被误判为损坏；打开归档前通过 libarchive-android 的 `Archive.setCharset` 把当前字符集覆盖为 UTF-8，使中文名条目可以正常读取。压缩包首次打开将支持的图片和视频流式写入私有缓存，成功后才写入完整清单；完整读取后只要发现 PDF，就提示先解压，无论是否同时存在图片或视频；取消或失败会清理未完成目录。对于固实压缩包，这比每翻一页重新解压前面的数据更可预测，但首次打开大书需要等待。

视频文件夹使用 `video-folder` 书籍类型，视频压缩包首次打开时也会把视频成员顺序解压到私有临时目录，再交给 Media3 播放。图片和视频在同一个文件夹或压缩包内时作为混合内容打开，按自然排序锁定水平翻页，并按当前页类型显示图片或视频控制。混合内容阅览目前标记为 WIP 实验性功能：翻页、切换、循环、自动续播、后台恢复等行为及其组合可能出现非预期表现，纯图片和纯视频内容不受影响。支持的扩展名包括 MP4、M4V、MKV、WebM、AVI、MOV、3GP、3G2、MPG、MPEG、TS、MTS、M2TS、FLV、WMV、OGV、VOB、RM 与 RMVB，实际编码能力由设备 Media3/系统解码器决定。

封面独立生成：先读取目录找到自然排序第一个媒体，图片解码首图，视频使用 Android 开源框架的 MediaMetadataRetriever 抽取首个视频的帧，按比例缩小到 1000 × 1000 范围并缓存 JPEG。视频文件夹直接读取 SAF URI；视频压缩包只提取首个视频成员到临时文件，生成封面后删除，保留单视频 4 GiB 上限。生成失败时书库保留占位图；不为了封面而完整展开整本压缩包。PDF 缓存一个本地副本，以满足 PdfRenderer 可寻址文件描述符的要求。

## 生命周期与性能

- I/O、解压、PDF 渲染和图片解码运行在 `Dispatchers.IO`；流式操作检查协程取消。
- 封面生成并行数为 2，同一本书的准备和封面生成分别通过 Mutex 串行；同一页面的文件缓存也串行写入，避免循环中多个可见副本争用临时文件。
- 图片阅读器采用 LazyColumn 或 HorizontalPager；循环只增加虚拟项目数，不复制媒体文件，记录的页码始终为真实页码。水平翻页预备前后各一页以便自然滑入；仅当前页的动画播放，垂直模式则播放可见动画；离屏、退到后台或退出时停止。
- 静态图片设置目标尺寸和像素上限；大型 APNG / AVIF 使用包装 Drawable 传递目标边界，使动画库按需采样。
- 缓存以 URI 摘要、修改时间和文件大小为键。源文件变化后重新生成；启动及退出阅读器时按最近使用顺序回收旧页面缓存，目标约 1.5 GiB。
- 自动回收阈值不是硬磁盘配额；当前打开的书籍、PDF 渲染图和封面可能使总缓存暂时超出阈值。设置中可手动清理。
- 视频按选定的垂直或水平方向离散翻页，混合内容固定为水平翻页；使用固定时长的滑入 / 滑出过渡而不连续线性滚动。纯视频过渡等待新视频首帧时保留旧画面，过渡期间当前播放器继续播放、下一播放器保持暂停，结束后同屏只保留一个播放器；混合 Pager 只允许已停靠的当前页播放。视图布局就绪与媒体准备状态独立维护，避免首次打开时因准备顺序覆盖布局状态而不自动播放。文件夹视频直接交给 Media3 读取 SAF URI，压缩包使用已解压的文件。播放结束自动进入下一段，设置可改为单段循环或仅预览。每段视频单独保存播放位置，完成播放后归零；书籍页码只由翻页更新，保存上一个视频的位置不会回写当前页码。
- 视频的双击只负责缩放；单击同步显示 / 隐藏底部工具栏和播放进度条。进度条左侧是播放 / 暂停按钮，上方显示当前时间与全长；拖动显示目标时间，松手提交定位，不添加暗色覆盖层。后台暂停不重新读取旧播放位置，退出释放播放器。

## 文件与隐私

正式 Manifest 不申请 INTERNET、外部存储读写或 MANAGE_EXTERNAL_STORAGE 权限。只读取用户授权的目录，不删除、移动或改写漫画原件。禁用备份与设备迁移，避免无效 URI 授权随应用数据迁移。

压缩包成员永远写入应用生成的序号文件名，不将成员路径直接拼接到输出目录。只接收常规图片和视频文件，忽略隐藏文件、macOS 元数据和非媒体条目，不提取符号链接。存在页数、递归深度、单页及总解压大小限制。

阅读进度按书籍 URI 保存；视频另按书籍和视频序号保存播放位置；设置、收藏、最近阅读持久化；缓存可清理且不影响原文件。设置中的“清除阅读记录”双击后会移除所有页码和视频位置。

测试使用的文件提供器只存在于单独的 `androidTest` APK；不会出现在正式应用中。测试样本为工具生成的原创占位图，无用户漫画内容。

## 系统支持

最低 API 29，编译 / 目标 API 36。现代 ARM64 手机为主要目标；x86_64 用于模拟器。启用预测返回回调并显示跟手过渡；低版本系统使用相同返回逻辑。Android 16 强制边到边布局所需的状态栏、导航栏和手势区域均由 Compose Insets 处理。

正式包的 `libarchive-jni.so`、`libavif_android.so`、`libandroidx.graphics.path.so` 的 ARM64 与 x86_64 ELF LOAD 段需具有至少 16 KB 对齐，APK 也需通过 `zipalign -P 16` 检查。构建和验证命令见测试记录。
